# 릴리스 절차 (소유자용)

이 문서는 exe 묶음을 만들어 올리는 순서입니다. 릴리스 파일은 [LICENSE](../LICENSE) 에 따라 **소유자가 허락한 사용자에게만** 제공합니다. 아래 어느 단계에도 토큰, 개인 경로, 특정 PC 의 값을 적지 마세요(명령은 모두 저장소 루트 기준 상대 경로 또는 `%TEMP%` 같은 환경변수 표기).

원칙: 커밋·푸시·병합·태그는 소유자가 확인한 뒤에만 합니다. 각 단계가 실패하면 다음 단계로 가지 말고 원인을 먼저 고칩니다.

## 1. 준비
1. 작업 브랜치에서 `CHANGELOG.md` 의 제목을 새 버전으로 바꾸고, `pyproject.toml` 의 `version` 과 맞춥니다.
2. 전체 시험은 로컬에서 돌리지 않고 4단계의 CI 로 확인합니다(15분 이상 걸림). 관련 파일만 먼저 `python -m pytest -q 파일명` 으로 돌려 봅니다.

## 2. 빌드
```
python packaging/build_exe.py --zip --out "%TEMP%\pcm-out"
```
- PyInstaller 는 임시 가상환경에만 설치되고 끝나면 치워집니다(버전은 `packaging/build_exe.py` 의 `PYINSTALLER_VERSION`).
- 결과: `pcmigrate-win.zip`(exe 묶음 폴더째). 빌드 폴더는 git 에 올라가지 않습니다.

## 3. 확인 (빌드한 결과물에서)
1. **개인정보 스캔**: zip 을 새 빈 폴더에 풀고, 풀린 파일 전체(텍스트와 바이너리)에서 이 PC 의 사용자 이름, 컴퓨터 이름, 홈 경로 문자열, 이메일, 토큰 모양(`ghp_`, `github_pat_`, `AKIA` 등)이 나오는지 검색합니다. 나오면 빌드 환경(경로, 환경변수)을 정리한 뒤 2단계부터 다시 합니다. 풀린 폴더는 확인 후 직접 지웁니다.
2. **버전 확인**: 풀린 폴더에서 `pcmigrate.exe --version` 이 새 버전을 보여 주는지.
3. **smoke 확인**: `pcmigrate.exe check-rules` 가 성공(종료 코드 0)하는지, `pcmigrate-gui.exe` 가 뜨고 닫히는지. 임시 폴더에서만 시험하고 실제 사용자 폴더는 건드리지 않습니다.
4. **SHA256SUMS 작성**: 올릴 파일(`pcmigrate-win.zip`, `field-guide.html` 등) 각각의 SHA-256 을 구해 `SHA256SUMS.txt` 에 `해시  파일이름` 형식으로 적습니다(`Get-FileHash -Algorithm SHA256 파일`).

## 4. 브랜치 푸시와 CI
1. 소유자가 커밋을 확인하고 브랜치를 푸시합니다.
2. GitHub Actions(`.github/workflows/tests.yml`)의 `test`, `robocopy` job 이 통과하는지 확인합니다. `perf` job 은 실패해도 전체를 막지 않지만 실패 사유는 기록합니다. 실패하면 고친 뒤 다시 푸시합니다.

## 5. main 병합과 태그
1. CI 가 통과한 브랜치만 소유자가 main 에 병합합니다.
2. 병합된 main 의 커밋에 `v<버전>` 태그를 붙여 푸시합니다(태그 푸시에서도 CI 가 돕니다).

## 6. GitHub 릴리스
1. 태그로 릴리스를 만들고 `CHANGELOG.md` 의 해당 항목을 본문으로 씁니다.
2. 3단계에서 확인한 파일과 `SHA256SUMS.txt` 를 첨부합니다. 빌드를 다시 했다면 3단계를 처음부터 다시 합니다.
3. **올린 파일 재대조**: 릴리스에서 파일을 새 빈 폴더로 내려받아 SHA-256 을 다시 구하고 `SHA256SUMS.txt` 와 한 글자씩 비교합니다. 하나라도 다르면 해당 첨부를 지우고 다시 올립니다.
4. 릴리스 접근 권한이 허락한 사용자에게만 열려 있는지 확인합니다(공개 설정이면 LICENSE 와 맞는지 소유자가 판단).

## 7. 기록
릴리스한 버전, CI 실행 결과, 재대조 결과를 `CHANGELOG.md` 또는 릴리스 본문에 사실대로 남깁니다(확인하지 못한 것은 '미확인'으로).
