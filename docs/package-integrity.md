# 설정 패키지 무결성 안내

## 도구가 확인해 주는 것
설정 패키지(.zip)에는 파일별 SHA-256 과 크기를 적은 `manifest.json` 이 들어 있습니다. 가져오기(import) 전에 도구가 zip 안의 실제 파일과 이 목록을 대조해서, 전송 중 일부가 깨졌거나 잘린 **우연한 손상**을 찾아냅니다.

## 한계: 악의적 변조는 잡지 못합니다
`manifest.json` 이 같은 zip 안에 들어 있으므로, 누군가 의도적으로 파일을 바꾸고 목록의 해시도 함께 고쳐 다시 압축하면 도구는 정상으로 봅니다. 서명이나 암호화는 하지 않습니다(전용 서명 기능 없음). 즉 이 검사는 "만든 그대로인가"가 아니라 "내부 목록과 내용이 서로 맞는가"만 확인합니다.

## 사용자가 할 일
1. **만든 직후 별도 경로로 해시를 기록합니다.** 패키지를 만든 PC 에서 PowerShell 로:

   ```
   Get-FileHash -Algorithm SHA256 .\패키지.zip
   ```

   나온 값을 zip 과 다른 곳(메모, 메신저, 종이 등)에 적어 둡니다. zip 옆에 같이 두면 같이 바뀔 수 있습니다.
2. **받은 PC 에서 같은 명령으로 값을 구해 대조합니다.** 한 글자라도 다르면 가져오지 마세요.
3. **USB/외장 드라이브로 옮길 때**: 꽂은 채로 바로 쓰지 말고 새 PC 로 복사한 뒤 위 대조를 하세요. 직접 건네받는 경우에도 해시는 사진/메모 등 다른 경로로 받으면 더 안전합니다.
4. **출처를 확신할 수 없는 패키지**는 복원(`import --yes`) 전에 반드시 미리보기(dry-run, `--yes` 없이 실행)를 먼저 하고, 대상 경로와 덮어쓸 파일 목록이 예상과 같은지 확인합니다. 규칙에 없는 경로, 시작 프로그램/스크립트 같은 실행 파일이 보이면 중단하세요. 신뢰할 수 없는 패키지는 쓰지 않는 것이 가장 안전합니다.

5. **출처를 모르는 설정 묶음은 복원하지 마세요.** 묶음 안에는 프로그램을 다음에 열 때 코드가 실행되는 파일이 있을 수 있습니다: 플러그인/매크로(SketchUp `.rb`, AutoCAD `.lsp .vlx .fas .arx .mnl`, Revit `.addin`, Rhino/Grasshopper `.rhp .gha`, `.node`, `.ahk`, VS Code `.vsix`, Gradle `.gradle`), 셸/편집기/Git 설정(`.bashrc`, `.bash_aliases`, `.vimrc`, `.emacs`, `.inputrc`, `.config\git\config`, `.gitconfig`). 도구는 이런 확장자와 홈 설정 위치를 기본으로 복원 거부 목록에 두고, 규칙이 그 확장자를 명시한 플러그인(SketchUp/AutoCAD/Revit 규칙의 `allow_extensions`)만 복원하며, 허용은 그 확장자를 적은 규칙 경로 아래의 파일에만 적용됩니다(예: AutoCAD `Support` 의 `.lsp` 허용은 `Plotters` 에는 적용되지 않음). 자동 실행 플러그인은 **직접 만든 묶음이거나 신뢰하는 사람에게 직접 받은 묶음에서만** 복원하세요. `.gitconfig` 는 흔히 쓰므로 경고 후 허용하니 복원 전에 내용을 확인하세요.

덮어쓰는 파일은 `.bak` 으로 먼저 보존되고, 가져오기 기록으로 되돌릴 수 있습니다(`undo-import`). 다만 이것이 변조된 패키지를 막아 주지는 않습니다.

## 가져오기 때 항목만 건너뛰는 경우와 패키지 전체를 거부하는 경우(stage68)
- **그 항목만 '복원 안 함'**(나머지는 정상 복원, 결과에 이유가 표시됨): 이 PC 에 없는 환경변수 위치(예: OneDrive 가 없는 PC 의 `%OneDrive%\Documents`, 지정하려면 `pcmigrate --env ONEDRIVE=D:\OneDrive import …`), 이 버전 규칙의 `exclude`/라이선스(`*.lic`)에 걸리는 옛 패키지의 파일(비밀번호 저장소 등), 복원 거부 확장자·위치.
- **패키지 전체 거부**(복원 안 함, `--only/--skip` 으로도 우회 불가): 경로 탈출(zip-slip)·안전하지 않은 이름, 알 수 없는 규칙 id, 규칙에 허용되지 않은 위치/허용 외 루트, 규칙에 선언된 경로 패턴 밖의 파일, 대상이 허용 루트 밖, 같은 대상으로 가는 중복 항목, 해시·크기 불일치. 선언 크기 합이 256 GiB 를 넘거나 zip 파일 실제 크기의 1000배(64 MiB 까지는 면제)를 넘는 패키지, 16 MiB 이상이면서 압축비가 1000배를 넘는 엔트리(거의 0 으로 채운 데이터, 압축 폭탄 의심)가 있는 패키지도 거부합니다. 보통 설정 파일(.ini/.xml/.json)의 압축비는 10~100배라 정상 패키지는 통과하지만, 0 으로 채운 큰 파일을 담은 패키지는 만들 때의 자체 검사에서도 거부됩니다.
- 대상 이름 자리에 같은 이름의 **폴더**가 있으면 미리보기부터 '실패(대상에 같은 이름의 폴더가 있음)'로 보이고, 실제 복원에서도 같은 결과입니다(폴더는 지우지 않음).
- 복원이 취소·예외로 **중간에 멈추면** 이미 쓴 파일의 복원 기록(`undo-import` 근거)을 저장하고, 여기까지의 결과 리포트(`--report`)를 남깁니다. 복원한 파일의 수정 시각은 패키지에 담긴 원본 시각(zip 시각, 2초 단위)으로 맞춥니다.
- `programs/*`(registry.json, winget.json, winget-list.txt)의 SHA-256 도 `manifest.json` 의 `programs_sha256` 에 담아 검증합니다. 이 키가 없는 옛 패키지는 기존처럼 읽되 '변조 여부를 확인할 수 없는 옛 형식' 경고를 표시합니다. 손상/변조된 프로그램 목록은 traceback 대신 '프로그램 목록을 읽을 수 없습니다' 로 안내하고, `winget-extract` 는 winget.json 의 스키마와 id 형식을 확인합니다.

## 알려진 한계(stage68)
- 규칙은 신 PC 에 **설치된 버전을 확인하지 않습니다**: 신 PC 에 없는 버전(AutoCAD 2020 등)의 설정 폴더도 만들어질 수 있습니다(규칙 경고에 안내, 쓰지 않는 폴더는 직접 삭제). 설치 목록과 연계한 자동 건너뜀은 규칙·프로그램 이름 형식이 제각각이라 오탐(정상 설정을 건너뜀) 위험이 커서 넣지 않았습니다.
- 복원한 설정 파일 **내용 안의** 구 PC 경로·사용자 이름은 바꾸지 않습니다(치환은 위험). 복원 결과와 체크리스트에 '설정 파일 안에 구 PC 경로가 들어 있을 수 있음' 경고만 표시합니다.
- `install_paths` 만으로 감지하는 규칙(ArchiCAD/SketchUp/Rhino)은 폴더만 남은 PC 나 같은 제조사의 다른 제품만 있는 PC 에서 오탐할 수 있습니다(규칙 notes 에 명시).
- QGIS 규칙은 폴더 단위 제외를 못 해 `python\plugins` 폴더를 빼지 못합니다(.py 는 복원 거부라 껍데기 폴더가 남을 수 있음, 규칙 경고에 안내). 비밀번호가 들어갈 수 있는 `QGIS3.ini` 는 기본으로 복원하지 않습니다.
- 기록 모드 초안은 이름에 `[ ]` 가 든 파일(`*`, `?` 처럼 glob 오인)을 담지 않습니다.
- Firefox 의 저장 비밀번호는 DPAPI 가 아니라 Firefox 자체 키 저장소에 있어 복사해도 쓸 수 없습니다(브라우저 규칙 경고 문구 정정).
- 복원 거부 확장자 표는 정적 목록입니다: 목록 밖 형식(예: 새 스크립트 형식)은 막지 못할 수 있어 출처 확인이 여전히 필요합니다.

## 재점검 반영(stage72)
- winget id 검사는 `+`(예: `Notepad++.Notepad++`)를 허용하는 하나의 규칙(`detect.valid_winget_id`)으로 checklist·install-check·winget-extract 가 함께 씁니다. 공백·따옴표·`; & |` 등 셸 문자는 계속 거부합니다. 한 항목의 id/로캘 문제는 그 줄만 '설치 명령을 만들지 못했습니다' 로 바뀌고 나머지 체크리스트는 계속됩니다.
- 복원 중 **중지(취소)** 하면 화면도 결과 화면으로 가서 '여기까지 복원된 파일'과 프로그램별 되돌리기가 보입니다(CLI 와 같은 부분 결과). 취소가 아닌 예외는 오류 화면으로 끝나지만 복원 기록은 저장되어 `undo-import` 로 되돌릴 수 있습니다.
- 규칙 폴더의 **파일 하나가 잘못돼도**(스키마 위반, JSON 오류, id 중복, 예: id 에 `.` 이 든 사용자 규칙) 그 규칙만 건너뛰고 나머지는 씁니다. 건너뛴 사유는 오류 로그와 표준 오류에 남고 `check-rules` 는 오류(종료 코드 1)로 보고합니다. 번들 규칙 25개는 영향이 없습니다.
- 기록 모드 후보에서 이름에 `%`(와 `* ? [ ]`)가 든 파일은 '설정 형식이 아니라 제외' 이유로 후보 표에 남고 규칙 초안에는 담지 않습니다.
- 레지스트리 프로그램 목록에서 Windows/Office 업데이트·핫픽스 항목(ReleaseType 이 Security Update/Update/Hotfix/Update Rollup/Critical Update 이거나 이름이 `(KB1234567)` 로 끝남)은 뺍니다. Store/MSIX 앱은 레지스트리에 없고 winget 목록(`winget export`)에만 보일 수 있으며, 앱 업데이트 노이즈는 완전히 걸러지지 않습니다(알려진 한계).
- 설치 폴더 설정과 규칙 복원 모두 `*.exe.config`/`*.dll.config`(로드할 코드를 바꿀 수 있는 실행 설정)는 거부합니다. 규칙이 `allow_extensions: [".exe.config"]` 등으로 명시하면 그 규칙에서만 허용됩니다.
- QGIS 규칙은 폴더 단위 제외·비 .py 파일 제외를 표현할 수 없고(규칙 `exclude` 는 파일 이름 기준, `paths` 는 프로필 폴더 하나), 프로필 하위 폴더 목록은 공식 문서로 확인되지 않아 나열하지 않았습니다. `python\plugins` 껍데기 폴더는 경고만 유지합니다.

## 3차 재점검 반영(stage74)
- **복원 중 예외(디스크 가득 참, 드라이브 분리 등)** 도 화면이 결과 화면으로 갑니다. 취소가 아닌 예외라도 이미 쓴 파일이 있으면(부분 결과가 있으면) 결과 화면에 '여기까지 복원된 파일'과 프로그램별 되돌리기가 보이고, 중단 이유(오류 문장)가 중지 안내 아래 한 줄로 표시됩니다. 오류 로그는 백엔드가 남깁니다. 부분 결과가 없는 예외는 기존 오류 화면입니다. 자동 흐름도 같습니다.
- **건너뛴 규칙 파일 안내**: 규칙 파일이 읽히지 않아 건너뛰면 터미널(stderr)뿐 아니라 화면에도 '읽을 수 없는 규칙 파일 N개를 건너뛰었습니다' 한 줄이 기존 경고 목록(가져오기 경고, 내보내기 안내, 체크 목록의 데이터/기타)으로 전달됩니다.
- **내장 규칙 우선**: 같은 규칙 폴더에서 id 가 겹치면 앱에 내장된 규칙 파일 이름(`vscode.json` 등)의 규칙이 이기고, 겹친 다른 이름의 사용자 규칙(예: `a_shadow.json`)은 건너뛰며 사유를 남깁니다. 사용자 규칙끼리의 중복 id 는 기존처럼 먼저 읽은 쪽만 쓰고 나머지는 건너뛰며 오류로 알립니다. 내장 규칙 이름과 다른 폴더(사용자가 `--rules` 로 지정한 폴더에 내장 규칙 파일이 없는 경우)의 규칙은 영향이 없습니다(알려진 한계: 그런 폴더에서 내장 id 와 같은 규칙을 만들면 그 규칙이 쓰입니다).
- **중단된 복원의 JSON**: 중단된 복원은 `written: true`, `dry_run: false`, `mode: "interrupted"` 이고, `import --json` 도 중단 결과(`interrupted`, `error`, 복원 기록 경로 `import_record`, 쓴 파일 목록 `written_files`, 개수 요약)를 JSON 으로 출력합니다(종료 코드 1).

## 새 리뷰 반영(stage78)
- **복원 거부 목록 보강**: 확장자 `.pth .pyd .pyc .pyz .egg .whl .ipy .otm .xla .ppam .ppa .psc1 .jsx .jsxbin` 추가(`.pth` 는 import 줄로 파이썬이 시작할 때마다 코드를 실행합니다). 홈의 `.cargo\config.toml`·`.cargo\config`(runner/wrapper), `.aws\config`(credential_process)·`.aws\credentials`, `.gradle\gradle.properties`, 어느 위치든 `.terraformrc`·`terraform.rc`·`npmrc`·`pip.ini`, `Notepad++\shortcuts.xml`(사용자 정의 실행 명령), `npm\etc
pmrc`, 폴더 `site-packages` 아래 전부를 경로 기반으로 거부합니다. 대소문자 변형도 같습니다. 규칙이 `allow_extensions` 나 마지막 패턴(`*.rb` 등)으로 명시한 플러그인 확장자는 기존대로 그 규칙에서 허용됩니다. 단 **실행/라이브러리 확장자(`.exe .dll .bat .ps1 …`)는 `allow_extensions` 뿐 아니라 path 의 마지막 패턴(`*.exe`)으로도 규칙에서 받지 않습니다**(규칙 로드 때 거부).
- **규칙 둘이 같은 파일을 가리킬 때**: 내보내기는 먼저 담은 규칙의 항목만 담고 뒤 규칙의 같은 파일은 제외로 기록합니다('다른 규칙이 이미 같은 파일을 담아 한 번만 담음'). `check-rules` 는 경로가 겹치는 규칙을 경고합니다(번들 규칙은 겹침 없음). 가져오기는 같은 대상으로 가는 중복 항목(예전 도구가 만든 패키지, 대소문자만 다른 경로)이 있어도 패키지 전체를 막지 않고 **뒤 항목만 '복원 안 함'**(먼저 나온 항목이 이김, 앞 항목을 `.bak` 으로 밀어내지 않음)으로 둡니다. 경로 탈출·알 수 없는 규칙 id 등 구조 위반은 전체 거부 그대로입니다.
- **긴 경로(260자 초과)**: 복원(`copy_file`)이 원본·대상·임시 파일 모두 긴 경로 접두로 다루고, 미리보기도 긴 경로의 존재 여부를 정확히 봅니다. 접두를 써도 만들 수 없는 길이(전체 32,000자 초과, 폴더/파일 이름 하나 255자 초과)는 미리보기부터 '실패(경로가 너무 깁니다)'로 표시합니다.
- **규칙 경고**: Civil 3D 규칙은 플롯 스타일(`.ctb/.stb`)·플로터 설정(`.pc3`)을 옮기지 않으며(AutoCAD 규칙은 Civil 3D PC 를 제외하고 Civil 3D 의 위치는 근거 미확인이라 paths 에 넣지 않음, 위치 확인 필요) Support 의 `.lsp .mnl .fas` 등은 허용 근거가 없어 복원 거부를 유지한다고 경고에 명시했습니다. SketchUp 규칙은 `.rb` 로더만 복원되고 `.rbe/.rbs` 본체가 거부되어 반쪽 확장이 생길 수 있음을 경고합니다(`.rbs` 허용 여부는 근거가 없어 바꾸지 않음).
- `checklist` 의 수동 설치 목록은 패키지 `registry.json` 의 이름·버전·게시자에서 ANSI 이스케이프·제어 문자를 지웁니다. 기록 모드 규칙 초안은 폴더(`dir`)로 묶은 항목이 스냅샷에 보이지 않은 파일까지 폴더째 담는다는 한계를 notes 에 적습니다(스키마는 폴더 안 일부 파일 지정을 지원하지 않음). 내보내기는 같은 폴더에 원래 이름의 파일이 있는 `<이름>.bak`·`<이름>.bak.N`(이 도구가 복원 때 만든 백업)을 다시 담지 않습니다(원래 이름이 없는 `.bak` 은 그대로 담음).
- **장기 과제(알려진 한계)**: 규칙 없는 선택 항목(extra)의 복원은 여전히 '거부 목록' 방식이라 목록에 없는 새 코드 실행 형식은 막지 못할 수 있습니다. 복원 허용을 설정 확장자 허용 목록(`settings_filter`)으로 바꾸는 것은 범위가 커서 이번에는 하지 않았고 장기 과제로 남깁니다.

## 최종 리뷰 반영(stage81)
- **규칙 `dest` 검증**: 사용자·기록 모드 규칙의 `dest`가 `a\b`, `a/*`, `con`, `a/b?`, `a//b`, `.`, 끝의 점/공백이면 규칙 로드(`parse_rule`, `check-rules`)에서 거부합니다(예전에는 내보내기가 파일을 모두 담은 뒤 패키지 검사에서 통째로 실패했습니다). 기록 모드 초안의 `dest`는 예약 이름(CON/NUL/COM1 …)에 `_` 를 붙입니다.
- **알 수 없는 규칙 id**: 패키지에 이 PC 의 규칙 폴더에 없는 규칙(예: 구 PC 의 사용자 규칙)의 항목이 있으면 패키지 전체를 막지 않고 **그 항목만 '복원 안 함'**(`skip_kind=unknown_rule`)으로 두고 나머지는 복원합니다. 사유에 '이 규칙 파일을 신 PC 의 rules 폴더 또는 --rules 폴더에 두면 복원할 수 있습니다' 안내가 붙습니다. 경로 탈출·규칙에 허용되지 않은 위치·허용 외 루트 같은 구조 위반은 전체 거부 그대로입니다.
- **OneDrive 클라우드 전용(온디맨드) 파일**: 내보내기는 `RECALL_ON_DATA_ACCESS`/`RECALL_ON_OPEN`/`OFFLINE` 속성이 있는 파일을 열어 읽지 않고(읽으면 대량 내려받기가 되므로) 담지 않습니다. manifest 의 `cloud_only`(개수와 앞 20개 경로)와 `skipped` 에 남기고 요약에 '클라우드 전용 N개는 내려받지 않고 제외했습니다' 를 보입니다. 파일을 이 PC 에 내려받은 뒤 다시 내보내면 담깁니다. 규칙 경로 전체의 총량 상한은 두지 않았습니다(알려진 한계: 큰 라이브러리 폴더는 모드 B 권장).
- **복원 거부 추가**: `.git` 폴더 아래 전부(`config` 의 `core.sshCommand`/`fsmonitor`, `hooks/*`), `.npmrc`(홈뿐 아니라 어느 위치든), 확장자 `.sh .bash .zsh .msix .appx .cdxml`. 규칙이 `allow_extensions`/마지막 패턴으로 명시한 확장자는 기존대로 허용되고 홈 `.gitconfig` 정책도 그대로입니다. extra 복원을 허용 목록 방식으로 바꾸는 것은 계속 **장기 과제**입니다.
- **Civil 3D 언어 폴더**: 규칙 경로의 `enu` 고정을 `*` 로 풀어 한국어 등 다른 언어 설치(`kor` 등)의 Support/Toolbox/Survey 도 수집합니다(한국어판의 실제 폴더 구조는 확인하지 못함 — 확인 필요). `enu` 로 만든 옛 패키지도 그대로 가져와집니다.
- **알려진 한계: 현지화된 OneDrive 문서 폴더**: Lumion/Enscape 의 OneDrive 후보는 영문 `Documents` 로 고정되어 있어, 한국어 OneDrive 로 문서 폴더를 리디렉션한 PC(예: `문서`)에서는 후보에서 빠질 수 있습니다. 근거가 확인되지 않은 경로는 규칙에 넣지 않았습니다. **제안**: Windows Known Folder API(`SHGetKnownFolderPath(FOLDERID_Documents)`)로 실제 문서 폴더 위치를 해석해 후보 루트로 추가하는 방법이 있습니다(ctypes 로 구현 가능하지만 환경변수 기반 경로 해석 전체에 영향을 주는 변경이라 이번에는 보류).
- **규칙 스키마**: 알 수 없는 키(`pahts`, `allow_extension` 같은 오타)는 최상위·`detect`·`paths` 모두에서 규칙 로드 오류입니다(규칙 파일 하나만 건너뛰는 방식은 그대로). `detect.install_paths` 는 `%환경변수%` 또는 드라이브 절대 경로로 시작해야 하고 `..` 를 쓸 수 없으며, `detect.registry_keys` 는 `HKLM`/`HKCU` 등으로 시작해야 합니다. Rhino 규칙의 notes 를 실제 감지 설정과 맞췄습니다. VS Code/JetBrains 규칙에 '실행 경로가 들어 있을 수 있으니 신뢰하는 묶음에서만' 경고를 추가했습니다.
- `checklist` 의 winget 자동/개별 설치 줄과 manifest 경고 항목도 ANSI·제어 문자를 지웁니다.
- **내보내기 종료 코드**: 사용 중이라 읽지 못해 빠진 파일이 있으면 종료 코드 **3(부분 성공)**, 읽기 외 실패(중복 경로 등)는 1, 모두 담았으면 0 입니다. 패키지는 검사를 통과해 만들어지지만 빠진 파일이 있다는 뜻이며 안내 줄은 그대로 나옵니다.
