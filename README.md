# pc-migration-tool (PC 이전 도우미)

구 Windows PC의 업무용(건축 CAD/BIM) 환경을 새 PC로 안전하게 옮기는 Python CLI입니다.
원본은 읽기만 하고, 복사 후 SHA-256으로 검증합니다. 설정 패키지 복원과 대용량 `transfer` 모두 덮어쓸 파일은 `.bak`으로 먼저 보존합니다
(자세한 방식은 아래 "덮어쓰기와 .bak" 참고). 규칙 폴더(`rules/`)가 없거나 비어 있으면 조용히 넘어가지 않고 오류로 멈춥니다.
설계 방침과 요구사항은 [CLAUDE.md](CLAUDE.md)를 보세요.

## 내려받기 (Python 없이 쓰려면)

Python 이 없는 PC 에서는 [릴리스 페이지](https://github.com/gyeongho-you/pc-migration-tool/releases)에서 받으세요.

| 파일 | 설명 |
|---|---|
| `pcmigrate-win.zip` | exe 묶음. 압축을 풀어 **폴더째** 쓰세요(`pcmigrate-gui.exe` 더블클릭). `_internal` 폴더를 지우거나 exe 만 따로 옮기지 마세요 |
| `field-guide.html` | 현장 안내(준비물, 순서, 명령, 막힐 때, 공식 링크). 인터넷 없이 브라우저로 열립니다 |
| `field-guide.md` | 같은 내용의 텍스트판(메모장이나 문서 앱으로 열림) |
| `SHA256SUMS.txt` | 위 파일들의 SHA-256. 받은 파일이 맞는지 `certutil -hashfile 파일 SHA256` 또는 `Get-FileHash 파일` 결과와 비교하세요 |

- 현장 안내 문서는 저장소의 [`docs/`](docs/) 폴더에도 있습니다([field-guide.html](docs/field-guide.html), [field-guide.md](docs/field-guide.md)).
- exe 는 **코드 서명이 없습니다.** 처음 실행하면 "Windows의 PC 보호" 창이 뜰 수 있으니 SHA-256 을 확인한 뒤 "추가 정보 → 실행" 을 누르세요.
- 이 도구는 실제 건축/토목 PC 에서 아직 검증되지 않은 부분이 많습니다(아래 "검증하지 못한 것" 참고).

## 설치

Python 3.10 이상이 필요하고 외부 패키지는 없습니다(대용량 전송은 Windows 내장 `robocopy`).

```
pip install -e .            # 개발용 설치(저장소의 rules/ 를 그대로 씀)
pip install .               # 일반 설치(규칙 JSON 이 패키지 안 pcmigrate/rules_data/ 로 함께 설치됨)
python -m pcmigrate check-rules   # 규칙 폴더가 읽히는지만 확인(설치 목록은 읽지 않음)
```

설치하지 않고 쓰려면 저장소 루트에서 `PYTHONPATH=src`(PowerShell: `$env:PYTHONPATH="src"`)를 지정합니다.

## 실행

```
python -m pcmigrate <명령> ...
```

`pcmigrate` 명령은 pip의 스크립트 폴더가 PATH에 없으면 "찾을 수 없다"고 나옵니다.
그럴 때는 위처럼 `python -m pcmigrate`를 쓰세요. 도움말: `python -m pcmigrate --help`

## 그래픽 화면(GUI)

명령어 없이 마우스로 쓸 수 있는 마법사입니다(Python 기본 `tkinter` 만 사용, 추가 설치 없음).

```
python -m pcmigrate.gui          # 또는: python -m pcmigrate gui
```

설치하지 않았다면 저장소 폴더에서 `PYTHONPATH=src` 와 함께 실행합니다. 더블클릭으로 열려면 아래 내용을 `pcmigrate-gui.bat`
로 저장해 두세요(경로는 실제 저장소 위치로 바꿉니다. 검은 창 없이 열려면 `python` 대신 `pythonw`).

```
@echo off
cd /d C:\path\to\pc-migration-tool
set PYTHONPATH=src
python -m pcmigrate.gui
pause
```

시작 화면에서 **큰 버튼 세 개** 중 하나를 고릅니다(실제 순서대로 ① 구 PC → ② 양쪽 PC → ③ 새 PC, 맨 아래 "전체 이전 순서 보기"로 12단계를 한눈에). 각 카드 아래 작은 글씨로 어느 PC 에서 하는 일인지 표시됩니다("구 PC에서" / "양쪽 PC에서: 보내는 쪽은 구 PC, 받는 쪽은 새 PC" / "새 PC에서"). 두 PC 를 연결하는 일(보내기·받기)은 ② 안에서만 하고, ①과 ③은 각자의 PC 안에서만 작업합니다.

| 선택 | 화면 순서 | 하는 일 |
|---|---|---|
| ① 쓰던 PC에서 준비하기(구 PC) | 프로그램 조사 → 자동 목록에 없는 프로그램 확인 → 해야 할 일 목록 → 설정 묶음 파일 만들기 | 설치 프로그램과 설정을 확인하고 `.zip` 설정 묶음 파일(패키지)을 만듭니다. 끝나면 "다음에 할 일" 상자("다음은 ② 내 파일 옮기기에서 이 설정 묶음을 새 PC로 보내 주세요(두 PC를 바로 연결하거나 외장 드라이브 사용)" → 새 PC에서 ③)가 나옵니다. 2단계 표와 설정 확인표의 "빠진 파일 예시"는 `폴더 보기`/`탐색기에서 보기`(줄 더블클릭·Enter)로 탐색기에서 볼 수 있습니다(파일을 열거나 실행하지 않고, 이 PC 의 로컬 디스크 경로만) |
| ② 내 파일 옮기기(도면·사진을 자동으로 찾아서, 예전 이름: 대용량 복사) — 양쪽 PC | 4단계: **찾기 → 방법 → 연결·복사 → 결과**(맨 위 단계 표시줄) | 1) **내 파일 찾기**(읽기만, 취소 가능)로 도면·사진·영상·문서가 모인 폴더 표가 나오고 직접 체크해서 고릅니다(자동 선택 없음, "제외 N곳", 클라우드 전용 파일 안내, "정크 파일 제외" 선택, "직접 폴더 추가", 폴더 줄 더블클릭/`폴더 보기`로 탐색기에서 보기). ①에서 만든 설정 묶음(.zip)이 있으면 표 맨 위에 **"① 에서 만든 설정 묶음 … 함께 보내기"** 체크 줄이 나옵니다(기본은 체크 해제, 없으면 줄이 안 보임). 체크하면 합계·미리보기·확인 창·결과에 "설정 묶음 1개 포함"이 보이고 보낼 목록에 들어갑니다(원본 zip 은 읽기만 하고, 보내는 동안만 임시 폴더에 복사본을 만들었다가 끝나면 지웁니다). 2) **옮기는 방법**: **두 PC를 바로 연결(추천)**(새 PC에서 "받는 쪽"을 열면 6자리 코드가 나오고, 구 PC에서 "보내는 쪽"으로 새 PC를 찾아 코드를 입력합니다. 내용은 암호화되지 않으므로 사설 네트워크에서만, 아래 `pcmigrate receive`/`send` 와 같은 기능) / 외장 드라이브 / 공유 폴더(고급). 3) 외장·공유 폴더는 아래 복사 화면으로 고른 폴더 목록을 넘깁니다. 폴더 하나만 직접 옮기거나 새 PC에서 2단계 확인을 하려면 1) 화면 아래의 "기존 방식" 링크를 쓰세요. 기존 복사 화면은 **외장 드라이브 / 랜선(네트워크) / 같은 PC** 중 고르고, 1단계(구 PC)·2단계(새 PC)로 복사하고 내용 확인(복사본이 원본과 같은지 비교, SHA-256)을 합니다(미리보기 → 복사, 진행률·남은 시간, 취소/이어받기). 원본/대상 입력칸과 주 버튼이 첫 화면에 보이고, 검사 방법·할 일·복사 전 확인은 "자세한 준비 사항 ▸" 안에 있습니다 |
| ③ 새 PC에서 설치하고 가져오기(신 PC) | 설정 묶음 파일 선택 → 프로그램 설치 확인(건너뛰기 가능) → 검사와 미리보기 → 복원 확인 → 결과 | 첫 화면에 "이 PC에서 찾은 설정 묶음" 목록(받은 폴더·바탕화면·다운로드·외장 드라이브, 최신 순)이 있으면 골라서 채울 수 있습니다. 받은 폴더는 ② 의 기본 받기 폴더(바탕화면 아래 `PC이전_받은파일_…`)와 마지막으로 받은 폴더입니다. ② 에서 '설정 묶음 함께 보내기'로 보낸 묶음은 받은 파일 폴더 바로 아래의 `설정 묶음` 폴더에 저장되며(구 PC 의 임시 폴더 경로나 사용자 이름은 받는 쪽에 남지 않음), 이전 버전이 보낸 깊은 경로의 묶음도 계속 찾습니다. 설치 확인에서는 묶음의 구 PC 프로그램이 이 PC에 이미 있는지 비교합니다(아래 "프로그램 설치 확인"). 미리보기를 보고 확인한 뒤에만 복원합니다. 결과 화면에 "백업 파일(.bak) 찾기"와 되돌리는 방법, "다음에 할 일" 체크 목록이 있습니다 |

각 카드 아래의 작은 **`추천대로 한 번에 ▸`** 버튼은 그 흐름을 한 화면에서 이어서 진행합니다(전체 단계 목록과 `중지` 버튼이 있는 화면 하나).
- ① 조사 → 해야 할 일 목록 → 바탕화면에 설정 묶음 파일 만들기. 자동 목록에 없는 프로그램은 아무것도 고르지 않고, 파일을 만들기 전에 위치 확인 창이 뜹니다.
- ② 질문 두 개(외장/랜선, 쓰던 PC/새 PC)로 방식을 정하고 미리보기부터 이어서 진행하며, 복사를 시작하기 전에는 기존 확인 창이 뜹니다.
- ③ 받은 폴더·바탕화면·다운로드·연결된 외장 드라이브에서 `pcmigrate-settings*.zip` 을 찾아(여러 개면 목록에서 선택, 최신 순) 미리보기와 프로그램 설치 확인까지 진행합니다. 설치 확인 지점에서는 설치 명령을 도구가 실행하지 않으며, 직접 설치한 뒤 `다시 확인`을 누르거나 `건너뛰기`/`확인했습니다`를 고릅니다. 복원은 **체크 두 개와 확인 창**을 거쳐야 실행됩니다. 찾지 못하면 이유와 "직접 고르기" 버튼이 나옵니다.
- 실패·취소·경고(복원되지 않는 파일, 읽지 못한 파일, 여유 공간 부족 등)가 있으면 그 자리에서 멈추고 이유와 "직접 진행하기" 버튼을 보여 줍니다. 확인 단계를 건너뛰는 길은 없습니다.

안전 장치는 명령줄과 같습니다.
- 원본은 읽기만 합니다. 쓰기 전에는 항상 "어디에 무엇이 써지는지" 확인 창이 뜹니다.
- 자동 목록(규칙)에 없는 프로그램은 자동으로 포함되지 않고, 직접 체크한 것만 들어갑니다(표 아래 "보이는 항목 전체 선택/해제" 단추로 한꺼번에 고를 수 있지만, 비밀 정보 가능성 항목은 전체 선택에서 빠지므로 직접 골라야 합니다). 비밀 정보 가능성이 있는 항목(붉게 표시)은
  "비밀 정보가 포함될 수 있음을 이해했습니다"에 동의해야 선택할 수 있습니다.
- 복원은 **체크 두 개**("미리보기에서 덮어쓸 파일을 확인했습니다", "백업 파일(.bak)이 남는다는 것을 이해했습니다") + 확인 창에서 "예"를 눌러야 실행됩니다. 실행 버튼에는 "복원 실행(파일 N개 덮어씀)"처럼 덮어쓸 개수가 적히고, 자동 목록 없이 선택 포함된 항목이 있으면 별도 동의가 필요합니다.
- 대용량 복사는 미리보기(쓰기 없음)를 먼저 실행해야 복사 버튼이 열리고, OneDrive 클라우드 전용 파일 포함은 기본 꺼짐입니다.
- 라이선스는 복원되지 않습니다.

오래 걸리는 작업(스캔, 탐지, 내보내기, 복원, 복사)은 백그라운드에서 돌아 화면이 멈추지 않으며, 규칙 없는 프로그램 탐지와 대용량 복사는
아래쪽 빨간 "중지" 버튼으로 멈출 수 있습니다(복사는 나중에 이어받기, 아래 "중지와 강제로 멈추기"). 오류는 한국어 한 문장과 "이렇게 해 보세요"로 나오고, 영문 예외 이름과 자세한 내용은 "상세 보기" 안에만 있습니다.
체크리스트 저장 파일에는 개인 정보가 들어 있으니 커밋/공유하지 마세요.

### 중지와 강제로 멈추기, 프로그램별 복원과 되돌리기, 폴더 전체 담기

- **중지**: 작업 중에는 아래 막대에 빨간 `중지` 버튼이 항상 있습니다(`추천대로 한 번에`에서도 같습니다). 누르면 바로 `중지하는 중…`으로 바뀌고 다시 누를 수 없습니다.
  15초가 지나도 작업이 끝나지 않으면 `아직 멈추지 않았습니다` 안내와 **지금 강제로 멈추기** 버튼이 나옵니다. 누르면 화면이 정상으로 돌아오고 만들던 임시 파일은 이어받기가 가능한 상태로 남으며,
  파일을 쓰는 새 작업은 옛 작업이 완전히 끝날 때까지 잠시 막힐 수 있습니다. 중지가 끝나면 이어받을 수 있는 작업인지(설정 묶음 파일 만들기, 큰 파일 복사), 이미 복원한 파일이 있을 수 있는지를 알려 줍니다.
- **프로그램별 복원 선택**: 새 PC의 미리보기에 프로그램별 표(복원 체크, 새로/덮어씀/같음)가 나옵니다. 체크를 끈 프로그램은 읽지도 쓰지도 않습니다. 체크를 바꾸면 미리보기를 선택대로 다시 계산하며(`--only`/`--skip` 과 같음),
  다시 계산하기 전에는 복원할 수 없습니다. 복원 확정 화면의 `덮어쓸 파일 N개`도 선택을 반영합니다.
- **프로그램별 되돌리기**: 결과 화면의 프로그램별 `되돌리기` 버튼은 먼저 미리보기(쓰기 없음)를 보여 주고, 확인한 뒤에만 덮어쓴 파일을 복원 전 백업 파일(.bak)로 되돌립니다(`pcmigrate undo-import` 와 같음).
  새로 생긴 파일은 지우지 않습니다. 복원 기록이 없으면 버튼이 꺼지고 이유가 적힙니다.
- **폴더 전체 담기**: `자동 목록에 없는 프로그램` 화면의 표에는 프로그램별 `설정 파일`(허용 방식으로 담길 개수)·`용량`·`제외`(설정 형식이 아니거나 캐시라서 빠지는 용량)가 나오고, 아래에 `선택 N개 · 설정 파일 M개 · 약 X MB` 합계가 나옵니다.
  표 높이는 최소 8줄이며 표 아래 경계를 끌어 늘릴 수 있습니다. 기본은 설정 파일만 담고, `고급 옵션 ▸`의 **폴더 전체 담기**(설정 파일이 아닌 파일도 포함, `--extra-mode all`)는 켤 때 한 번 더 확인합니다.
- 마지막 화면(구 PC)은 상자 사이 여백을 줄이고 설정 확인표를 접어 한 화면에 들어오게 했습니다. `추천대로 한 번에`의 마지막 화면에도 `읽지 못해 제외된 파일 N개 / 이 파일들만 다시 담기`가 있고,
  모두 담기면 `끝났지만 확인 필요`가 `완료`로 바뀝니다. 내보내기가 오류로 멈추면 `다시 시도(저장점부터 이어서)`, `처음부터 다시 만들기`, `직접 진행하기` 버튼이 나옵니다.

### 작업 현황 카드와 전체 단계

- 창 맨 위에 **"전체 단계 2/4"** 와 단계 이름(예: `✔ 1 조사 → 2 목록 밖 프로그램 → 3 할 일 → 4 묶음 만들기`)이 표시됩니다(구 PC/새 PC 4단계, 외장·랜선 복사는 2단계).
- 오래 걸리는 작업 화면(프로그램 조사, 자동 목록에 없는 프로그램 찾기, 해야 할 일 목록, 설정 묶음 파일 만들기, 검사, 복원, 큰 파일 복사/검사)에는
  제목 바로 아래에 **작업 현황 카드**가 나옵니다. 기본으로는 세 가지만 보입니다.
  1. 큰 글씨 한 줄: 지금 하는 일(예: `② 복사 중 — 12,431 / 50,003개 파일 (24%)`)
  2. 진행 막대
  3. `남은 시간 약 N분`(추정할 수 없으면 "계산 중"). 문제가 생기면 같은 줄 오른쪽에 한 줄로 알려 줍니다.
  나머지는 카드 안의 **"자세히 ▸"** 를 누르면 펼쳐집니다(하단 상태줄은 카드가 보이는 화면에서는 같은 말을 되풀이하지 않고, 작업이 없을 때는 진행 막대가 숨겨집니다).
  - 단계 표시줄: `① 조사 → ② 복사 → ③ 검사 → ④ 완료`(끝난 단계는 ✔, 지금 단계는 강조, 작업마다 자기 단계가 나옵니다)
  - 지표: 파일 완료/전체, 용량, 속도, 경과 시간, 남은 시간
  - 지금 처리 중인 폴더/파일 한 줄(긴 경로는 줄여 보이고 마우스를 올리면 전체 경로)
  - 카운터 칩: `✔ 성공` / `↷ 건너뜀` / `⚠ 읽지 못함(사용 중)` / `✖ 실패` — 0 이 아니면 색과 아이콘으로 강조되고, 누르면 해당 목록이 열립니다
  - "문제가 있나요?" 한 줄 요약(없으면 "지금까지 문제 없음")과 마지막 메시지 한 줄
- 작업이 끝나도 결과 요약(`④ 완료 — …`)이 카드에 남아 있어 한눈에 확인할 수 있습니다.

### 오류 로그

예기치 않은 오류가 나면 전체 내용(traceback 포함)이 아래 파일에 한 건씩 덧붙여집니다.

```
%LOCALAPPDATA%\pcmigrate\logs\errors-YYYYMMDD.log      (쓸 수 없으면 %TEMP%\pcmigrate-logs\)
```

- 한 건에는 시각, 도구 버전, 실행한 명령/화면 이름, 예외 종류와 메시지, 전체 traceback 이 들어갑니다.
  파일은 하루 단위이고 5MB 를 넘으면 `errors-YYYYMMDD.1.log` 로 이어지며, 최근 10개 파일만 남깁니다.
- 설치 프로그램 목록과 파일 내용은 기록하지 않습니다. **오류 로그에는 파일 경로가 들어 있으니 다른 사람에게 보내기 전에 확인하세요.**
- GUI: 오류 대화상자의 **문제 보고서 저장 / 로그 폴더 열기 / 오류 내용 복사** 버튼(보고서와 복사 내용의 내 폴더 경로는 `%USERPROFILE%` 로 바뀝니다), 메인 창 아래쪽의 **오류 로그 열기** 버튼으로 바로 열 수 있습니다.
  (`%TEMP%\pcmigrate-gui.log` 에는 계속 이벤트 이름만 남습니다.)
- 명령줄: `pcmigrate logs` 가 로그 폴더 경로와 최근 오류 한 건의 요약을 보여 주고, `pcmigrate logs --open` 은 탐색기로 엽니다.
  예상하지 못한 오류는 traceback 대신 "예상하지 못한 오류가 났습니다. 자세한 내용은 … 에 기록했습니다." 두 줄과 종료 코드 1 로 끝나며,
  Ctrl+C 는 "중단했습니다." 와 종료 코드 130, 잘못된 옵션(argparse 오류)은 종료 코드 2 입니다.

화면 사용 팁
- 각 화면 오른쪽 위의 **`?`** 버튼(또는 F1 키)을 누르면 "무엇을 하는 화면인지 / 안전한지 / 다음 단계"를 짧게 보여 줍니다.
- 버튼이 눌러지지 않을 때는 버튼 옆에 이유가 적혀 있습니다(예: "미리보기를 먼저 실행해 주세요").
- 키보드: Tab 으로 이동, Enter 로 기본 버튼 실행, Alt+H/B/N 으로 "처음 화면으로/이전/다음"(밑줄 글자), Esc 는 대화상자 닫기와 작업 취소에만 씁니다(화면을 되돌리지 않습니다). 표에서는 Space 로 선택/해제합니다.
- 맨 아래 **고정 막대**에 "처음 화면으로 / 이전"(왼쪽)과 주 버튼(오른쪽 끝, 파랑)이 있어 스크롤해도 사라지지 않습니다. 덮어쓰기 같은 되돌리기 어려운 실행은 주황색이고, 마지막 화면의 주 버튼은 "완료"입니다. 내용이 길면 "아래에 더 있습니다" 표시가 뜹니다.
- 경로 입력: 구 PC의 설정 묶음 파일은 기본으로 바탕화면의 `pcmigrate-settings.zip`(**바탕화면에 만들기** 버튼으로 되돌림)입니다. 붙여넣은 경로의 앞뒤 공백과 따옴표는 자동으로 지우고, 탐색기 주소창의 경로를 복사해 붙여넣어도 되며, **드라이브 선택** 목록에 외장 드라이브가 표시됩니다. 랜선 2단계의 확인용 목록 파일은 **자동 찾기** 버튼이 찾아 줍니다. 입력칸은 한 줄 전체를 쓰고 찾아보기·드라이브 선택 버튼은 그 아랫줄에 있어 좁은 창에서도 파일 이름 끝이 잘리지 않습니다.
- 고급 옵션(접힘): 대용량 복사에는 "4GB가 넘는 파일을 조각으로 나눠 복사(FAT32 외장 디스크용)"(새 PC에서 `pcmigrate join` 으로 합침), 설정 묶음 파일 만들기에는 "임시 파일 위치"(큰 파일을 잠시 복제하는 폴더, 비우면 기본)가 있습니다. 설정 파일에 Git 명령 실행 설정이 있을 수 있으면 미리보기/결과에 한 줄로 알려 줍니다.
- 화면 크기: 시작 크기는 화면 배율(DPI)에 맞춰 커지되 화면을 넘지 않고, 오른쪽 위 **A+ / A-** 로 글자 크기를 바꿉니다(기본 본문 11pt). ✔ ✖ ⚠ 를 현재 글꼴이 그릴 수 없으면 자동으로 `[OK] [X] [!]` 글자 표시로 바뀌고, 환경변수 `PCMIGRATE_TEXT_ICONS` 는 강제 옵션입니다(`1` = 항상 글자 표시, `0` = 항상 그림 글자).
- 표의 긴 경로는 줄여서 보이며, 마우스를 올리면 전체 경로가 나옵니다. 열 제목을 누르면 정렬됩니다.
- 해야 할 일 목록은 항목에 체크하면서 진행할 수 있고(저장하면 체크한 항목이 `[x]` 로 남음), "관련 없는 경고도 모두 보기"로 숨긴 경고를 볼 수 있습니다.
- 화면의 모든 한국어 문구는 `src/pcmigrate/gui/texts.py` 한 곳에 있습니다(문구를 고칠 때 이 파일만 수정).

Python 없이 exe 로 실행하는 방법과 빌드 방법은 아래 "exe 로 실행하기"를, 1TB 이전은 "1TB 이전 가이드"를 보세요.

## exe 로 실행하기 (Python 없이)

구 PC 에 Python 이 없어도 됩니다. 빌드한 폴더(`pcmigrate\`)를 USB 나 공유 폴더로 옮겨서 실행하세요.

```
pcmigrate\
  pcmigrate-gui.exe     ← 더블클릭하면 마법사 화면이 열립니다(콘솔 창 없음)
  pcmigrate.exe         ← 명령 프롬프트/PowerShell 에서 쓰는 명령줄 버전
  _internal\            ← 실행에 필요한 파일(지우거나 exe 만 따로 옮기지 마세요)
```

- **관리자 권한이 필요 없습니다.** 일반 사용자로 실행하세요(`asInvoker`). 바탕화면, 한글/공백이 들어간 폴더, USB 드라이브 어디에서든 실행됩니다.
- exe 에는 `rules\`, `selftransfer\` 와 Python 실행기, tkinter 가 모두 들어 있습니다(실제 Python 이 PATH 에 없는 환경에서 `--version`, `scan`, `checklist`, `discover`, `transfer`, `manifest`, `verify`, GUI 실행을 확인했습니다. 아래 "검증한 범위" 참고).
- 명령줄 예: `pcmigrate.exe --version`, `pcmigrate.exe transfer D:\프로젝트 E:\이전 --dry-run`

### 처음 실행할 때 (SmartScreen)

서명하지 않은 exe 라서 처음 실행하면 파란 "Windows의 PC 보호" 창이 뜰 수 있습니다. 받은 파일이 맞는지 확인한 뒤
**추가 정보 → 실행** 을 누르세요. 보낸 사람이 알려 준 SHA-256 값과 아래 명령의 결과가 같은지 먼저 비교하세요.

```
cmd:         certutil -hashfile pcmigrate-gui.exe SHA256
PowerShell:  Get-FileHash .\pcmigrate-gui.exe -Algorithm SHA256
```

회사 백신이 막으면(오탐) 폴더를 예외로 등록하거나 담당자에게 허용을 요청하세요. 빌드할 때마다 exe 의 바이트가 달라지므로
**받은 빌드와 함께 전달받은 SHA-256 값**을 기준으로 확인합니다.

### 폴더 방식(onedir)과 단일 파일(onefile) — 기본은 폴더 방식

| 기준 | 폴더 방식 `onedir` (기본) | 단일 파일 `onefile` |
|---|---|---|
| 크기(측정) | 폴더 29.4MB (zip 14.5MB), exe 는 각 2.6MB | exe 2개 각 12.1MB |
| 시작 시간(측정, 이 PC) | `--version` 0.26~0.31초, GUI 창이 6초 안에 열림 | **매 실행 3.4~4.4초**(실행할 때마다 임시 폴더에 풀고 검사), GUI 는 6초 뒤에도 창이 없었음 |
| 백신 오탐 | 상대적으로 적음 | 자기 압축 해제 방식이라 오탐이 더 잦다고 알려져 있음(이 PC 에서는 직접 확인 못 함) |
| 임시 폴더 제한 | 필요 없음 | `%TEMP%` 에 쓰고 실행해야 함(보안 정책이 막으면 실행 안 됨) |
| 배포 | 폴더째 복사(zip 으로 묶기 쉬움) | exe 파일만 복사 |

그래서 기본은 폴더 방식입니다. 파일 하나로만 전달해야 하면 `--mode onefile` 로 빌드할 수 있습니다.

### 직접 빌드하기

Windows 에서 저장소 루트에서 실행합니다. PyInstaller 는 **전역 Python 에 설치하지 않고**
`%TEMP%\pcm-build` 아래 새 가상환경에만 설치하며(버전 고정: `packaging/build_exe.py` 의 `PYINSTALLER_VERSION`),
끝나면 그 폴더와 중간 산출물을 지웁니다.

```
python packaging\build_exe.py                       # dist\pcmigrate\ (git 에 올라가지 않음)
python packaging\build_exe.py --zip                 # 같은 결과를 pcmigrate-win.zip 으로도 묶음
python packaging\build_exe.py --mode onefile        # exe 단일 파일(느림, 위 표 참고)
python packaging\build_exe.py --out %TEMP%\pcm-out  # 결과 위치 지정(PowerShell: $env:TEMP\pcm-out)
```

스크립트 없이 직접 만들려면(임시 가상환경에서) 같은 일을 하는 명령은 다음과 같습니다. `rules` 폴더를 `--add-data` 로 함께 넣어야 하며,
번들된 `rules\` 는 프로그램이 자동으로 찾습니다.

```
pyinstaller --noconfirm --noconsole --paths src --add-data "rules;rules" -n pcmigrate-gui packaging\gui_entry.py
pyinstaller --noconfirm --console   --paths src --add-data "rules;rules" -n pcmigrate     packaging\cli_entry.py
```

빌드가 끝나면 각 exe 의 크기와 **SHA-256** 을 출력하고 `pcmigrate.exe --version` 과 `pcmigrate.exe check-rules`(번들된 규칙이 실제로 읽히는지)로 확인합니다.
`--work` 로 지정한 폴더는 **비어 있거나 이 스크립트가 만든 표식 파일(`.pcmigrate-build-work`)이 있을 때만** 쓰고 빌드 뒤 정리합니다. 비어 있지 않은데 표식이 없는 폴더나 드라이브 루트/사용자 폴더/저장소를 포함하는 폴더는 아무것도 지우지 않고 종료 코드 2 로 거부합니다.
출력된 SHA-256 을 받는 사람에게 함께 알려 주세요. exe 와 `dist\`, `build\`, `*.spec` 은 `.gitignore` 대상이라 커밋되지 않습니다.

검증한 범위(Windows 11, 일반 사용자 권한, PATH 에서 Python 제외): `--version`, `scan`, `checklist --output`, `discover`,
`transfer`(미리보기/실복사/목록 저장), `verify`(정상/변조 감지), `manifest`, 한글·공백 경로, GUI 를 띄워 정상 종료.
**검증하지 못한 것**: 아주 깨끗한 새 Windows 설치(이 PC 는 개발 PC 라 Visual C++ 런타임 등이 이미 있음), USB 드라이브에서의 실행,
실제 SmartScreen/백신 반응, 창 모드 exe 에서 복사 도구 창이 번쩍이는지 눈으로 확인(코드에서는 숨김 옵션을 줌),
**실제 OneDrive PC 에서의 클라우드 전용 파일 동작**(감지/건너뜀이 현장 환경에서 기대대로인지 확인 필요). 참고로 robocopy 의 `/xa:O`(오프라인 속성 제외)가 클라우드 전용 파일을 정확히 건너뛰는지는
공식 문서로 확인되지 않았고, **이 도구는 `/xa:O` 에 의존하지 않습니다**(자체 속성 검사로 감지).

## 1TB 이전 가이드 (외장 드라이브 / 랜선)

데이터가 크고(약 1TB) 밤새 돌려도 끊겨도 이어받고 결과를 믿을 수 있어야 하는 상황을 기준으로 정리했습니다.
**두 방식을 모두 지원합니다.** GUI 의 "대용량 복사" 화면 맨 위 **"어떻게 옮기시나요?"** 에서 고릅니다.

### 두 방식 한눈에 비교

| | 외장 드라이브 | 랜선(네트워크) | 같은 PC 안 |
|---|---|---|---|
| 흐름 | 구 PC → 외장 → 새 PC (복사 2번) | 구 PC → 새 PC 공유 폴더 (복사 1번) | 폴더 → 폴더 |
| 준비물 | NTFS 로 포맷한 외장 SSD/HDD, USB 3.x 포트 | 랜선, (LAN 포트가 없으면) USB 기가비트 랜 어댑터, 새 PC 에 비밀번호 있는 계정과 공유 폴더 | 없음 |
| 속도 한계 | USB 3.x 외장 SSD 는 보통 수백 MB/s(장치마다 다름, 이 PC 에서 측정하지 못함) | 기가비트 이론 최대 약 110MB/s (100Mbps 면 약 11MB/s) | 디스크 속도 |
| 검사 방법 | 1단계: 외장에 복사한 파일을 다시 읽어 확인 + 목록 파일 저장 / 2단계: 외장의 목록 파일과 새 PC 의 복사본을 비교(외장 원본을 다시 읽지 않음) | 1단계: 복사하며 원본 해시를 계산해 목록 파일 저장(네트워크로 다시 읽지 않음) / 2단계: 새 PC 에서 목록 파일과 로컬 복사본 비교 | 복사본을 다시 읽어 확인 |
| 막히기 쉬운 곳 | FAT32 형식(4GB 초과 파일 불가), USB 2.0 포트, 드라이브 문자 변경 | 공유 설정, 계정/비밀번호, 네트워크 프로필, 링크 속도, 절전 | 여유 공간 |

**랜선으로 충분한 경우**: 기가비트(1000Mbps) 연결이 확인되고 새 PC 에 공유 폴더를 만들 수 있으며, 복사가 한 번뿐이라 전체 시간이 외장보다 짧을 때.
**외장 드라이브가 나은 경우**: 네트워크 설정이 어렵거나 연결이 자주 끊길 때, 두 PC 를 한 곳에 둘 수 없을 때, 단순한 구조로 이어받고 싶을 때,
또는 외장 드라이브의 실제 속도가 기가비트 랜보다 확실히 빠를 때.
(측정값과 이론값을 구분해서 보세요: 이 표의 기가비트 110MB/s 는 이론값이고, 외장 SSD 속도는 제품마다 다릅니다.)

### 흐름별 체크리스트

**외장 드라이브**
1. 준비물: 외장 SSD/HDD(**NTFS 로 포맷**), USB 3.x 포트, 구 PC 의 모든 프로그램 종료, 노트북은 전원 연결.
2. (구 PC, 1단계) 화면에서 "외장 드라이브" → 1단계. 원본 폴더와 외장의 빈 폴더를 고르고 **미리보기 → 복사 시작**.
   끝나면 결과가 "복사 완료(정확함) N / 실패 0" 인지 확인합니다. 외장 폴더에 확인용 목록 파일(`.pcmigrate-manifest.jsonl`)이 함께 저장됩니다.
3. 외장을 안전하게 제거해 새 PC 에 꽂습니다(**드라이브 문자가 바뀌면** 화면에 경고가 뜹니다).
4. (새 PC, 2단계) "외장 드라이브" → 2단계. 외장의 복사 폴더와 새 PC 의 폴더를 고르고 **미리보기 → 복사 시작**. 외장의 목록 파일로 새 PC 의 복사본을 검사합니다.
5. 실패 0 을 확인한 **뒤에만** 구 PC 의 원본/외장을 정리하세요.

**랜선(네트워크)**
1. 준비물: 랜선(CAT5e 이상), 필요하면 USB 기가비트 랜 어댑터, 새 PC 의 접속 계정과 공유 폴더 — 아래 "네트워크 준비" 참고.
2. (구 PC, 1단계) 탐색기에서 `\\새PC의IP\공유이름` 이 열리는지, 파일을 만들 수 있는지 먼저 확인합니다.
   화면에서 "랜선(네트워크)" → 1단계. 대상에 `\\새PC의IP\공유이름\폴더` 를 입력하고 **미리보기 → 복사 시작**.
   끝나면 목록 파일이 새 PC 의 공유 폴더에 함께 저장됩니다. 이 단계의 결과는 "복사 완료(검사는 새 PC 에서)" 입니다.
3. (새 PC, 2단계) "랜선(네트워크)" → 2단계. 목록 파일과 복사된 폴더를 고르고 **검사 시작**. 구 PC 와 네트워크를 거치지 않고 로컬 파일만 읽습니다(폴더는 읽기만).
4. 실패 0 을 확인한 **뒤에만** 구 PC 의 원본을 정리하세요.

문제가 생겼을 때 확인할 곳: 외장은 **드라이브 문자와 형식(NTFS)**, USB 3.x 포트(느리면 화면에 USB 2.0 확인 안내), 연결 상태 /
랜선은 **ping, 공유 폴더 접속, 링크 속도(1000Mbps), 네트워크 프로필, 절전 설정**(느리면 화면에 100Mbps 확인 안내).

### 네트워크 준비 (랜선으로 옮길 때)

**환경(공유기, 보안 소프트웨어, Windows 버전)에 따라 다를 수 있습니다.** 아래는 일반적인 예시이고, 화면의 방식 선택 상자 안 "네트워크 준비 도움말" 링크에도 같은 내용이 있습니다.

1. **연결**: 같은 공유기/스위치에 두 PC 를 모두 **유선**으로 연결하거나, 두 PC 를 랜선 하나로 직접 연결합니다. LAN 포트가 없으면 USB 기가비트 랜 어댑터를 씁니다.
2. **랜선 직결일 때 고정 IP (예시)**: 설정 > 네트워크 및 인터넷 > 이더넷 > IP 할당 > 편집 > 수동 > IPv4
   - 구 PC: IP `192.168.50.1`, 서브넷 마스크 `255.255.255.0`, **기본 게이트웨이는 비워 둡니다**.
   - 새 PC: IP `192.168.50.2`, 서브넷 마스크 `255.255.255.0`, 기본 게이트웨이는 비워 둡니다.
   - 두 PC 모두 같은 설정 화면에서 **네트워크 프로필을 "개인"** 으로 바꿉니다(공용이면 접속이 막힙니다).
   명령으로 확인/설정할 수도 있습니다(관리자 권한 필요, 이름 "이더넷" 은 `ipconfig` 로 확인).
   ```
   cmd:         netsh interface ip set address name="이더넷" static 192.168.50.2 255.255.255.0
   PowerShell:  New-NetIPAddress -InterfaceAlias "이더넷" -IPAddress 192.168.50.2 -PrefixLength 24
                Set-NetConnectionProfile -InterfaceAlias "이더넷" -NetworkCategory Private
   ```
3. **새 PC 에서 공유 폴더 만들기**: ① **비밀번호가 있는** 로컬 계정 하나를 만듭니다(비밀번호가 없으면 네트워크 접속이 막힙니다).
   ② 받을 폴더(예: `D:\이전`)를 만들고 속성 > 공유 > 고급 공유에서 공유한 뒤, 그 계정에 **변경(쓰기)** 권한을 줍니다.
   ```
   cmd:         net share 이전=D:\이전 /GRANT:접속계정,CHANGE
   PowerShell:  New-SmbShare -Name 이전 -Path D:\이전 -ChangeAccess 접속계정
   ```
   (`net share` 는 아래 [각주 1](#net-note) 참고. `New-SmbShare` 문서: [참고 링크](#참고-링크) 절)
4. **접속 테스트(구 PC 에서)**:
   ```
   cmd / PowerShell:  ping 192.168.50.2
   cmd:               net use \\192.168.50.2\이전 /user:접속계정
   PowerShell:        Test-Path \\192.168.50.2\이전
   ```
   탐색기 주소창에 `\\192.168.50.2\이전` 을 입력해 열리는지, 폴더 안에 새 텍스트 파일을 만들었다 지워서 **쓰기**가 되는지 확인합니다.
   접속이 꼬였으면 `net use * /delete` 로 기존 연결을 끊고 다시 시도합니다. (`net use` 는 [각주 1](#net-note) 참고)
5. **링크 속도 확인**: 설정 > 네트워크 및 인터넷 > 이더넷 > 속성의 "링크 속도"가 **1000/1000(Mbps)** 인지 봅니다(PowerShell: `Get-NetAdapter | Format-Table Name, LinkSpeed`).
   100Mbps 로 나오면 케이블(CAT5e 이상인지)이나 어댑터를 바꿔 보세요. 기가비트에서 이론 최대는 약 110MB/s 이고 실제는 환경에 따라 크게 다릅니다.
6. **전송 중 (받는 PC 는 직접 해야 합니다)**: 이 도구는 **보내는 PC(도구를 실행하는 PC)의 절전만** 막습니다. 공유 폴더를 가진 **받는 새 PC 는 도구가 건드리지 못하므로**
   사용자가 전송 전에 직접 ① 전원 어댑터를 연결하고 ② 잠자기를 꺼 두세요. 안 그러면 새 PC 가 잠들어 공유 폴더가 끊깁니다(끊겨도 같은 설정으로 다시 실행하면 이어받습니다).
   ```
   cmd:           powercfg /change standby-timeout-ac 0      ← 전원 연결 시 잠자기까지의 시간(분). 0 = 안 함 (powercfg /? 도움말 기준)
   되돌리기:      powercfg /change standby-timeout-ac 30     ← 전송 전에 적어 둔 원래 값(분)으로. 현재 값은 `powercfg /query` 로 확인
   ```
   (관리자 권한이 필요할 수 있습니다. 이 README 에서는 확인하지 못했습니다.)
   네트워크 어댑터의 전원 절약도 끕니다: **장치 관리자 > 네트워크 어댑터 > (사용 중인 어댑터) 속성 > 전원 관리 탭 > "전원을 절약하기 위해 이 장치를 끌 수 있음" 체크 해제**.
   PowerShell 로 하려면 `Set-NetAdapterPowerManagement` 문서([참고 링크](#참고-링크) 절)를 보세요(옵션 이름은 이 README 에서 확인하지 못했습니다).
   전송이 끝나면 위 설정을 원래대로 되돌리세요(체크 다시 켜기, 잠자기 시간 복구).

**SMB 서명과 로그온 주의**: Microsoft 문서([Control SMB signing behavior](https://learn.microsoft.com/en-us/windows-server/storage/file-server/smb-signing))에 따르면
Windows 11 24H2 의 **Pro/Enterprise/Education 은 SMB 서명을 기본으로 요구**하고 **Home 은 요구하지 않습니다**. 서명을 지원하지 못하는 NAS 나 게스트(익명) 접속은 실패할 수 있습니다.
Microsoft 는 서명을 끄는 우회를 권장하지 않으므로, 이 문서도 끄는 방법을 안내하지 않습니다. **이 도구는 SMB 서명 등 Windows 의 네트워크/보안 설정을 바꾸지 않습니다**(필요하면 사용자가 직접 확인).
또한 **비밀번호가 없는 로컬 계정은 네트워크 로그온이 되지 않습니다**: [Accounts: Limit local account use of blank passwords to console logon only](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/security-policy-settings/accounts-limit-local-account-use-of-blank-passwords-to-console-logon-only).

<a id="net-note"></a>
**각주 1 (net use / net share)**: Microsoft Learn 의 현재 Windows commands 목록에는 `net use`, `net share` 페이지가 없습니다. 두 명령은 Windows 11 에서도 동작하지만
공식 문서는 보관본([보관본 문서(Windows Server 2012 R2/2012)](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-server-2012-r2-and-2012/gg651155(v=ws.11)))뿐이라, 옵션은 `net use /?`, `net share /?` 로 직접 확인하세요.

**공유 폴더에 계속 접속되지 않을 때(시스템 오류 67 "네트워크 이름을 찾을 수 없습니다", 1222 "네트워크를 사용할 수 없습니다" 등).** 위 준비 단계(연결, 같은 IP 대역, 네트워크 프로필 "개인", 방화벽의 파일 및 프린터 공유, 비밀번호 있는 계정)과 `Test-NetConnection <새 PC IP> -Port 445` 를 한 번씩 확인했는데도 해결되지 않으면, 설정에 오래 매달리지 말고 **외장 SSD/HDD 방식으로 바꾸세요**("1TB 이전 가이드"의 외장 드라이브 흐름). 회사 보안 소프트웨어나 네트워크 정책이 SMB 접속을 막는 경우는 현장에서 고치기 어렵습니다. 외장 방식은 네트워크 없이 같은 해시 검증과 이어받기를 그대로 씁니다.

네트워크 오류는 쉬운 문구로 나옵니다: 공유 폴더를 찾을 수 없음(IP/공유 이름/프로필 확인), 로그인 실패(계정/비밀번호), 이미 다른 계정으로 연결됨(`net use * /delete`), 쓰기 권한 없음(공유 권한).

### 1TB 예상 시간 (측정 기반 추정 + 한계)

**이 PC(18코어, NVMe SSD, 백신 켜짐)에서 측정한 값** — 합성 데이터(`%TEMP%`), 원본과 대상이 같은 디스크라서 실제 외장/네트워크 환경과 다릅니다.

| 항목 | 측정값 | 비고 |
|---|---|---|
| 해시 속도(파일 캐시 상태) | 1개 스레드 약 800MB/s, 2개 약 1.7GB/s | CPU 한계. 실제 디스크/네트워크는 이보다 훨씬 느려 병목이 아님 |
| 읽기 청크 64KB~16MB | 600~860MB/s 로 큰 차이 없음 | 4MiB 로 정함(느린 장치에서 큰 순차 읽기가 유리, 오버헤드 무시 가능). 파일 캐시 영향이 커서 콜드 읽기 차이는 이 측정으로 알 수 없음 |
| 복사 도구 방식(1GB×2, 로컬) | 일반 약 1.9GB/s, `/J` 약 0.95GB/s, `/Z`(기본) 약 0.65GB/s | 캐시 영향이 큼. `/Z` 는 끊겨도 파일 중간부터 이어받는 대신 로컬에서는 느림 |
| 작은 파일 20,000개 복사 | `/Z` 약 300~650개/초, `/MT:4` 약 1,100~1,250개/초 | 그래서 복사 스레드 기본값을 4 로 함(느린 HDD/USB 는 `--copy-threads 1`) |
| 작은 파일 50,000개(합계 200MB) 전체 | 복사 51초 + 검사 57초 = 총 108초, 약 2.1ms/파일 | 수정 전에는 파일당 약 6.4ms(복사 `/MT` 없음, 해시 버퍼 낭비) |
| 이어받기(이미 끝난 50,000개) | 약 5초, 원본/대상 읽기 0 | 상태 파일의 해시 재사용 |
| 검사만 다시 / 목록 비교 | 약 24초 / 약 21초 (50,000개) | 대상만 읽음 |
| 상태 파일 / 목록 파일 크기 | 각 약 7.3MB (50,000개) → 파일당 약 150바이트 | 줄 단위 JSON, 100만 개면 약 150MB |
| 최대 메모리(작업 집합) | 약 65~73MB (50,000개) | 파일당 약 0.6KB 로 보면 100만 개는 약 0.7GB, 300만 개는 약 2GB (외삽, 불확실) |

**1TB 외삽** (대용량 파일 위주라고 가정, 단순 모델: 복사 = 1TB ÷ 속도, 검사 = 원본/대상을 다시 읽는 시간으로 복사의 1~2배). 속도는 **가정**이며 이 PC 에서 측정한 값이 아닙니다.
실제는 가장 느린 구간(구 PC 디스크, 케이블/포트, 대상 디스크)이 결정합니다.

| 지속 속도(가정) | 대표 상황 | 복사 | 복사 + 검사 합계 |
|---|---|---|---|
| 30MB/s | USB 2.0 포트의 외장 | 약 9.3시간 | 약 19~28시간 |
| 100MB/s | 기가비트 랜 실측 수준, HDD | 약 2.8시간 | 약 5.6~8.3시간 |
| 110MB/s | 기가비트 랜 이론 최대 | 약 2.5시간 | 약 5.0~7.6시간 |
| 400MB/s | USB 3.x 외장 SSD(가정) | 약 0.7시간 | 약 1.4~2.1시간 |
| 1000MB/s | NVMe 끼리(가정) | 약 0.3시간 | 약 0.6~0.8시간 |

- **네트워크(랜선)는 복사본을 네트워크로 다시 읽지 않고**(검사는 새 PC 로컬 디스크에서) 하므로 표의 "검사" 부분이 줄어듭니다. 새 PC 의 로컬 검사 시간은 별도로 더해집니다.
- 작은 파일이 많으면 위 시간에 파일당 약 2ms(SSD 기준, HDD 는 몇 배)가 더해집니다(100만 개면 약 35분 이상).
- **불확실성**: 외장/랜 실제 속도, 백신, 파일 크기 분포, 디스크 상태에 따라 2배 이상 달라질 수 있습니다. 먼저 폴더 하나로 시험 복사해 속도를 보고 판단하세요.
  화면의 남은 시간은 최근 30초 속도로 계속 다시 계산합니다.

### 안전하게 돌리기 위한 약속

- **절전 방지**: 복사 중에는 시스템이 잠자기로 들어가지 않게 합니다(화면 끄기는 건드리지 않음). 끝나거나 오류가 나면 원래대로 되돌리며, 되돌리기에 실패해도 프로그램이 끝나면 Windows 가 자동으로 해제합니다. 실패하면 경고만 하고 계속하니 전원 설정도 확인하세요. 노트북은 전원을 연결하세요. 명령줄에서 끄려면 `--no-keep-awake`.
- **OneDrive "클라우드 전용" 파일**: 클라우드에만 있는 파일은 읽는 순간 자동으로 내려받아지는 것이 일반적인 동작입니다(이번에 공식 문서로 확인하지는 못했습니다). 그러면 **구 PC 의 디스크 공간을 쓰고 로컬 상태가 바뀔 수** 있고, 1TB 규모면 시간과 공간이 크게 늘어납니다.
  이 도구는 **파일 속성으로 클라우드 전용 파일을 감지해 기본으로 건너뛰고**, 리포트에 `cloud_only` 로 남깁니다(`--include-cloud` 를 줄 때만 포함). 필요한 파일은 복사 전에 직접 내려받아 두세요:
  탐색기에서 해당 폴더를 우클릭 > **"이 디바이스에 항상 유지"** ([Microsoft 안내](https://support.microsoft.com/en-us/office/0e6860d3-d9f3-4971-b321-7092438fb38e)). 내려받는 동안 디스크 여유 공간을 확인하세요.
- **프로그램 종료 후 복사**: CAD/BIM 등 파일을 쓰는 프로그램을 모두 닫으세요. 사용 중인 파일은 복사/검사에 실패하고 "다른 프로그램이 파일을 사용 중" 으로 안내됩니다. 닫은 뒤 "실패한 것만 다시 시도"를 누르세요.
- **여유 공간 사전 검사**: 대상의 여유 공간이 원본 총량 + 5% 보다 적으면 시작하지 않습니다(네트워크 경로는 조회되면 같은 검사, 안 되면 경고만).
- **FAT32 차단**: 대상이 FAT32 인데 4GB 보다 큰 파일이 있으면 복사 전에 막습니다. NTFS 로 포맷하거나 다른 드라이브를 쓰세요(포맷이 어려우면 아래 `--split-large` 로 조각으로 나눠 저장하고 새 PC 에서 `join` 으로 합칩니다). exFAT 는 경고만 합니다.
- **드라이브 분리 감지**: 복사 중 외장 드라이브가 빠지면 즉시 멈추고 "드라이브가 분리되었습니다. 다시 연결하면 이어받습니다" 라고 알립니다. 다시 연결해 같은 설정으로 실행하면 이어받고, 드라이브 문자가 바뀌었으면 경고합니다.
- **xref/데이터 단축은 절대 경로를 씁니다**: 도면의 외부 참조, 이미지, 데이터 연결은 `D:\프로젝트\...` 같은 절대 경로로 저장된 것이 많습니다. 결과 화면에 원본의 절대 경로와 최상위 폴더 구조를 보여 주고,
  복원한 위치가 원래 경로와 다르면 노란 경고가 뜹니다. 새 PC 의 드라이브 문자와 폴더 구조를 구 PC 와 같게 맞추는 것이 가장 안전합니다.
- **검사가 끝나 "실패 0" 을 확인하기 전에는 구 PC 의 원본을 삭제하거나 PC 를 포맷하지 마세요.** 이 도구는 원본을 지우지 않습니다.
- 긴 경로(260자 초과)는 읽기/검사에 `\\?\` 접두를 써서 처리합니다. 그래도 읽지 못하면 "경로가 너무 깁니다" 로 알려 줍니다.

### 읽기 횟수 (큰 파일 기준, 파일 하나당)

복사 도구(robocopy)의 읽기와 이 도구의 검사 읽기를 모두 센 값입니다. "측정" 은 위 합성 데이터에서 확인한 값입니다.

| 상황 | 원본 읽기 | 대상(복사본) 읽기 | 이전 단계(11단계) 대비 |
|---|---|---|---|
| 로컬/외장 첫 복사 | 2번(복사 1 + 해시 1) | 1번 | 같음 |
| 이어받기(이미 검사 끝난 파일) | 0 (측정) | 0 (측정) | 상태 파일로 건너뜀(같음) |
| 검사만 다시(`--verify-only`) | 0 (측정, 상태 파일의 원본 해시 재사용) | 1번(항상 다시 읽음) | 11단계의 `--strict`(원본 1 + 대상 1)보다 원본 읽기 1번 줄어듦 |
| 외장 2단계(`--use-manifest`) | 외장 복사 1번만(해시 읽기 0, 측정) | 1번 | 외장 해시 읽기 1번 줄어듦 |
| 랜선 1단계(`--manifest-out`, 대상이 네트워크) | 2번 | 0 (네트워크로 다시 읽지 않음) | 네트워크 재읽기 1번 줄어듦, 새 PC 에서 로컬 검사로 대체 |
| 새 PC 검사(`verify`) | 0 | 1번(로컬) | 새 기능 |

첫 복사의 원본 2번 읽기(복사 도구 1 + 해시 1)는 이번 단계에서 줄이지 못했습니다(복사 도구를 쓰는 한 유지됩니다).

### 새 명령과 옵션

```
python -m pcmigrate transfer <원본> <대상> [옵션]
  --verify-only            복사 없이 원본/대상을 비교만(대상은 항상 다시 읽음)
  --retry-failed           전체를 다시 복사하지 않고 검사가 끝나지 않았거나 실패한 파일만 다시 복사/검사
  --workers N              파일 단위 병렬 검사 개수(기본 2, 최대 8). 느린 USB/HDD 는 1 이 나을 수 있음
  --copy-threads N         복사 도구가 동시에 복사할 파일 수(기본 4, 1~16)
  --chunk-mb N             읽기 청크(MB, 기본 4)
  --copy-mode MODE         restartable(기본, /Z: 파일 중간부터 이어받음) / normal / unbuffered(/J)
  --manifest-out FILE      원본 기준 해시 목록(.jsonl) 저장. 대상이 네트워크면 대상 검사를 미루고 새 PC 에서 verify
  --use-manifest FILE      원본 해시를 이 목록에서 가져와 원본을 다시 읽지 않음(외장 2단계)
  --split-large            4GB 넘는 파일을 조각(<이름>.pcm001, .pcm002 ...)으로 나눠 저장(아래 설명). 새 PC 에서 join 으로 합침
  --verify-dest / --no-verify-dest   --manifest-out 과 함께 대상 검사를 지금 할지(기본: 네트워크면 미룸)
  --no-keep-awake          절전 방지를 끔

python -m pcmigrate manifest <원본> --out <목록.jsonl>            # 원본(로컬)을 읽어 해시 목록만 만들기(읽기 전용)
python -m pcmigrate verify --manifest <목록.jsonl> --target <폴더> [--report 결과.json] [--no-extras]
                                                                   # 새 PC: 목록과 로컬 폴더 비교(누락/내용 다름/추가 파일), 폴더는 읽기만
python -m pcmigrate join <조각 폴더 또는 첫 조각(.pcm001)> --output <합칠 폴더> [--manifest <목록.jsonl>] [--dry-run]
                                                                   # 새 PC: --split-large 로 나눈 조각을 원래 파일로 합침(조각은 읽기만)
```

- **4GB 분할 파일(`--split-large`)**: 켜면 4GiB-1 바이트를 넘는 파일을 복사 도구(robocopy)에서 빼고 이 도구가 `<이름>.pcm001`, `.pcm002` … 조각(기본 4000MiB)으로 같은 폴더에 씁니다. 대상이 NTFS/exFAT 여도 켜면 나눕니다. 옵션 없이 FAT32 대상에 4GB 넘는 파일이 있으면 전과 같이 복사 전에 막고 `--split-large` 를 안내합니다. 원본은 한 번만 읽으며 조각별·전체 SHA-256 을 함께 구하고, 해시 목록(`--manifest-out`, 형식 버전 2)에는 `parts: [{name,size,sha256}]` 로 기록됩니다(버전 1 목록도 읽습니다). 조각은 임시 이름에 쓰고 확정한 뒤에만 조각 이름이 되므로 이어받기는 조각 단위입니다(검사 끝난 조각은 건너뛰고 쓰던 조각은 처음부터). 같은 이름의 다른 조각은 덮어쓰기 전에 `.bak` 으로 보존하고, 이번 조각 수보다 번호가 큰 옛 조각도 `.bak` 으로 옮깁니다. `verify`/`--verify-only` 는 조각을 순서대로 이어 읽어 원본 전체 해시와 비교합니다. **새 PC 에서는 `join` 으로 합쳐야 원래 파일이 됩니다**: NTFS 드라이브를 `--output` 으로 주면 조각 폴더의 하위 구조 그대로 합치고(여유 공간·FAT32 사전 점검, 기존 파일은 `.bak`, 조각 해시와 전체 해시를 목록 `--manifest`(없으면 조각 폴더의 `.pcmigrate-manifest.jsonl`, 그것도 없으면 `.pcmigrate-state.json` 의 조각 해시)와 대조한 뒤에만 이름을 바꿈), 조각은 지우지 않습니다. 한계: 외장 2단계(`--use-manifest`)에서는 조각이 일반 파일로 복사되고 합치기는 새 PC 에서 합니다. 원본이 복사 도중 바뀌면 그 파일은 실패로 알립니다.

#### 내 파일 자동 찾기와 여러 폴더 한 번에 옮기기(`find-data`, `transfer --from-selection`)

옮길 폴더를 사람이 일일이 찾지 않도록, 도구가 고정 드라이브를 **읽기 전용**으로 훑어 도면/사진/영상/문서/압축이 있는 폴더를 종류별로 보여 주고, 고른 폴더만 한 번에 옮깁니다.

```
pcmigrate find-data [--roots 폴더 ...] [--categories design,photo,video,doc,archive,other] [--min-size 100MB] [--max-depth 4]
                    [--time-limit 초] [--include-removable] [--json] [--output-selection 선택.json]
pcmigrate transfer --from-selection 선택.json <대상> [--exclude-junk [--exclude-backup-copies]] [--manifest-out 목록.jsonl] [--skip-done-items] [일반 transfer 옵션]
```

- **찾기**: 기본은 모든 고정 드라이브(네트워크/CD 제외, 이동식은 `--include-removable`). 자동 제외: Windows, Program Files, ProgramData, AppData, 휴지통, System Volume Information, node_modules, `.git`, 임시/캐시 폴더, 설정 규칙(`rules/*.json`)이 담당하는 경로. 바로가기/정션은 따라가지 않고, OneDrive 클라우드 전용 파일은 내려받지 않고 '클라우드 전용 N개'로 따로 셉니다. 읽지 못한 곳은 기록하고 계속하며, `--time-limit` 을 넘으면 그때까지의 결과만 보여 줍니다(요약에 표시).
- **결과**: 프로젝트/자료 폴더 후보(폴더 하나에 설계/사진/영상 파일이 직접 있거나 문서·압축 3개 이상이면 그 폴더를 하나로 묶음, 최대 깊이 4)마다 종류별 개수·용량, 폴더 전체 용량, 가장 최근 수정일, 대표 확장자, 근거를 보여 줍니다. 사용자 기본 폴더(문서/바탕화면/사진/동영상/다운로드/음악)는 `--roots` 없이 실행할 때 따로 나옵니다. 분류 표(근거 등급 A/B/C)는 `src/pcmigrate/find_data.py` 한 곳입니다. 이름(확장자)만 보며 파일 내용은 열지 않습니다.
- **선택 파일**: `--output-selection` 은 후보마다 `include: false` 인 JSON 을 씁니다(자동 선택 안 함). 옮길 폴더의 `include` 를 `true` 로 바꾸고 `transfer --from-selection` 에 줍니다. 선택 파일은 훑은 폴더 밖에 저장하세요(`--roots` 로 폴더를 지정한 경우 그 안에는 거부).
- **전송**: 항목마다 기존 `transfer` 를 한 번씩 실행하므로 해시 검사, `.bak` 보존, 파일 단위 이어받기, `--strict`, `--retry-failed`, `--split-large` 가 그대로 적용됩니다. 대상 구조는 `<대상>\<드라이브 문자>\<원본 경로>` 입니다(`D:\프로젝트\A` → `<대상>\D\프로젝트\A`, 네트워크는 `UNC\서버\공유\…`). 같은 폴더를 두 번 고르거나 부모와 자식을 함께 고르면 자식은 빼서 중복 복사를 막습니다(리포트의 `dropped`). 대상이 원본 안이면 시작하지 않고 거부하며, 시작 전에 선택 합계(선택 파일의 용량, 대상에 이미 있는 양은 뺌, 5% 여유)와 대상 여유 공간을 비교합니다. 폴더 하나가 실패해도(예: FAT32 의 4GB 초과 파일) 나머지는 계속하고 폴더별 성공/실패와 전체 합계를 요약합니다. 대상 폴더의 `.pcmigrate-multi.json` 에 폴더별 진행(pending/done/failed)이 남고, 중간에 멈춘 뒤 같은 명령을 다시 실행하면 이어받습니다(`--skip-done-items` 는 끝난 폴더를 다시 확인하지 않음). `--manifest-out` 은 폴더별 해시 목록을 하나로 합쳐(경로 앞에 `D/프로젝트/…` 가 붙음) 새 PC 에서 `verify --manifest 목록 --target <대상>` 한 번으로 비교합니다. `--report` 는 폴더별 결과가 든 JSON 하나를 씁니다. `--from-selection` 에서는 `--log/--state-file/--use-manifest` 를 쓸 수 없습니다(폴더마다 대상 안에 기록).
- **정크 제외(`transfer --exclude-junk`, 단일 폴더/`--from-selection` 공통)**: 기본은 아무것도 제외하지 않습니다. 켜면 robocopy `/XF` `/XD` 로 Thumbs.db, ehthumbs.db, desktop.ini, `~$*` Office 잠금, `~WRL*.tmp`, `*.tmp`, CAD 잠금(`*.dwl` `*.dwl2` `*.ac$` `*.rhl`), `.DS_Store`, `__MACOSX`, `$RECYCLE.BIN`, System Volume Information, node_modules 를 복사하지 않고, 제외한 개수/용량을 결과(`junk_excluded`)와 요약에 표시합니다. 사용자 작업일 수 있는 `*.bak`, AutoCAD 자동 저장 `*.sv$`, `.git` 은 목록에 없습니다. `--exclude-backup-copies` 를 더하면 Revit 백업 사본(`이름.0001.rvt` 등), `*_backup` 폴더, Rhino `*.3dmbak`, SketchUp `*.skb` 도 뺍니다. 목록과 근거 등급은 `src/pcmigrate/junk.py` 한 곳입니다.
- **한계**: 찾기는 이름/확장자와 폴더 구조만으로 판단하므로 후보가 아닌 폴더가 나오거나 빠질 수 있습니다(직접 확인 후 include). 폴더 단위로 옮기면 후보 안의 분류되지 않은 파일(작은 파일 포함)도 함께 복사됩니다. USB 외장 SSD/HDD 는 '고정'으로 보일 수 있으니 옮길 대상 드라이브가 훑히지 않게 `--roots` 로 지정하세요. 대용량 PC 에서는 훑는 데 오래 걸릴 수 있습니다(`--time-limit`).

- 검사를 새 PC 로 미룬 복사(랜선/네트워크 + `--manifest-out`)는 CLI JSON 의 `success` 가 `false`, `verification_complete` 가 `false` 이고 "복사 완료, 검증 전: 새 PC 에서 verify 필요" 로 안내합니다(GUI 도 '성공' 대신 '복사 완료(검증 전)'). 건너뛴 정션/링크(앞 200개)는 `[안내]` 로 나열하고 리포트의 `skipped_link_paths` 에 남깁니다. `verify` 결과의 `manifest_errors` 는 구 PC 에서 읽지 못해 목록에서 빠진 파일 수이며 0 이 아니면 `success` 가 `false` 입니다. `import` 에서 복원 위치가 링크를 거쳐 복원하지 않은 파일은 `rejected` 로 세고 실패와 같이 취급합니다(링크 너머에는 쓰지 않음).
- **출력 형식**: `export`/`import`/`verify`/`transfer` 는 기본으로 사람이 읽는 한국어 요약(핵심 숫자 + "다음 할 일" 한 줄)을 표준 출력에 냅니다. 이전의 JSON 이 필요하면 `--json` 을 붙이세요(스크립트/GUI 용). `transfer --dry-run` 정상 미리보기는 JSON 의 `success` 가 `true` 이고 `preview: true` 입니다(검증이 아직 없다는 뜻의 `verification_complete: false` 는 그대로).
- **경로 인자**: 양끝의 공백과 따옴표(`"` `'`)는 자동으로 지웁니다(지웠다고 알려 줍니다. 빈 값은 여전히 거부). 드라이브 문자 없이 역슬래시 하나로 시작하는 경로는 거부하고(네트워크는 역슬래시 두 개로 시작), 상대 경로는 현재 폴더 기준 절대 경로로 풀어 보여 줍니다. `export --output` 에 확장자가 없으면 `.zip` 을 붙이고, `.zip` 이 아니면 경고합니다.
- `transfer --clean-state`: 전송이 성공하고 검사까지 통과했을 때만 대상 폴더의 기록 파일(`.pcmigrate-*`)을 지웁니다(복사한 데이터는 그대로). 지우면 다음 실행 때 전체를 다시 검사합니다.
- `verify` 는 대상 폴더를 읽기만 합니다. 결과 파일(`--report`)을 검사할 폴더 안에 저장하려 하면 거부합니다.
- 복사 도구 실행 중 진행 상황(바이트, 속도, 남은 시간)이 CLI 는 stderr 에 10초마다, GUI 는 작업 현황 카드의 진행 막대에 표시됩니다. 속도가 계속 느리면 외장은 "USB 2.0 확인"(40MB/s 미만),
  네트워크는 "링크 속도 100Mbps 확인"(11MB/s 미만) 안내가 서로 다른 문구로 나옵니다.
- 복사 도구의 종료 코드/오류 줄을 원인별로 나눕니다: 사용 중, 권한, 경로 길이, 공간 부족, 연결 끊김, 네트워크 접속 실패(찾을 수 없음/로그인/충돌/쓰기 권한).
- 상태 파일(`.pcmigrate-state.json`)은 파일마다 한 줄씩 덧붙이는 **줄 단위 JSON** 이라 파일이 수백만 개여도 이어받기 중 전체를 다시 쓰지 않으며, 전원이 꺼져 마지막 줄이 잘려도 나머지는 쓸 수 있습니다.
- 이어받기와 `.bak` 보존: 대상 폴더의 `.pcmigrate-preserve.json` 이 "이 복사가 시작됐는가"를 기억합니다. 중간에 멈춘 복사를 같은 설정으로 다시 실행하면(기록이 `copying`) 대상의 중간 파일 중 **원본의 앞부분과 바이트까지 같은 것**만 우리가 쓰던 것으로 보고 `.bak` 으로 옮기지 않고 이어서 씁니다(그 밖의 다른 파일, 예를 들어 멈춘 사이에 사용자가 고친 파일은 `.bak` 으로 보존합니다). 원본 경로가 이전 기록과 다르면(대소문자·상대 경로 차이는 같은 경로로 보고, 드라이브 문자가 바뀐 경우 등은 이어받기로 보지 않고) 경고합니다. 복사가 끝난 뒤(`done`) 원본을 고쳐 다시 실행하면 바뀐 파일의 이전 사본이 `.bak` 으로 남습니다. 대상이 비어 있으면 대상 파일을 검사하지 않으므로 추가 비용이 없고, 대상에 파일이 있으면 파일마다 `stat` 한 번(100만 개에 약 1분 내외, 같은 폴더 안 이름 변경은 파일당 수 ms)이 듭니다.
- `.pcmigrate-` 로 시작하는 기록 파일(상태, 로그, 목록, 보존 기록)은 다른 폴더로 복사하지 않습니다(외장 2단계에서 외장의 상태 파일이 새 PC 의 상태 파일을 덮어쓰는 일을 막기 위함).

#### LAN 직접 전송: 두 PC 에서 도구를 켜고 코드로 연결(`pcmigrate receive` / `pcmigrate send`)

공유 폴더(SMB)는 계정, 방화벽, 서비스 설정에 막혀 오류 67/1222 로 자주 실패합니다. 이 방식은 SMB 없이 **도구 자체가 TCP 로** 전송합니다(같은 공유기/스위치, 또는 랜선 직결의 링크로컬 169.254.x.x 에서도 동작). 표준 라이브러리만 씁니다.

```
새 PC : pcmigrate receive [--dest 폴더] [--port N] [--code 6자리] [--bind IP] [--allow-public] [--no-discovery]
구 PC : pcmigrate send <주소[:포트]|자동> --code 코드 (--from-selection 선택.json | 원본폴더...)
                       [--exclude-junk [--exclude-backup-copies]] [--include-cloud] [--layout auto|flat|drive] [--chunk-kb N]
                       [--report 결과.json] [--json] [--allow-public]
        pcmigrate send <주소[:포트]|자동> [--code 코드] --diagnose      # 연결 문제 한 줄 진단(아무것도 바꾸지 않음)
```

1. 새 PC 에서 `pcmigrate receive` 를 실행합니다. 받는 폴더(기본: 바탕화면 아래 새 폴더), **접속 주소 목록**(사설/링크로컬 주소), **6자리 페어링 코드**가 표시됩니다. 처음 실행하면 Windows 방화벽 창이 뜰 수 있으니 **개인 네트워크만 허용**하세요(도구는 방화벽을 바꾸지 않습니다).
2. 구 PC 에서 `pcmigrate send 자동 --code 123456 --from-selection 선택.json` 을 실행합니다. `자동` 은 UDP 브로드캐스트(고정 포트 47831)로 같은 서브넷의 receive 를 찾아 이름/주소를 보여 줍니다. 못 찾으면 새 PC 화면의 주소를 직접 적으세요(`192.168.0.12:47830`). 원본은 읽기만 합니다.
3. 끝나면 양쪽에 집계(**정확함/불일치/누락**)가 나옵니다. 새 PC 의 받은 폴더에 `.pcmigrate-manifest.jsonl` 이 남아 기존 `pcmigrate verify --manifest <목록> --target <받은 폴더>` 로 다시 검사할 수 있습니다. 끊기면 같은 명령(같은 코드)을 다시 실행하면 이어받습니다.

**보안(꼭 읽으세요)**: 코드로 서로를 확인하고(HMAC-SHA256 챌린지-응답, 코드 자체는 전송하지 않음) 모든 프레임의 변조/재전송을 검사하지만 **전송 내용은 암호화하지 않습니다**(표준 라이브러리만으로 AES 를 쓸 수 없음). 믿을 수 있는 **사설 LAN 에서만** 쓰세요. 6자리 코드는 100만 가지뿐이라 엿본 핸드셰이크에 대한 오프라인 대입에 약합니다(PBKDF2 로 비용만 올림). 코드는 10분 안에 한 번 짝지어야 하고, 5번 틀리면 잠기며(실패마다 지연이 늘어남), 한 번에 송신 PC 한 대만 받습니다. 공인(인터넷) 주소면 경고하고 `--allow-public` 이 있어야만 씁니다.

**프로토콜 요약**(자세한 것은 `src/pcmigrate/lan_protocol.py` 상단 주석): 프레임 = 16바이트 헤더(magic, 버전, 종류, 길이, 순번) + 페이로드 + HMAC-SHA256(32). 핸드셰이크는 HELLO → CHALLENGE(nonce, salt) → AUTH(HMAC 증명) → AUTH_OK(수신 측 증명)로 상호 인증하고 방향별 세션 키를 만듭니다. 이어서 PLAN(파일 수/총량/최대 파일 크기/청크 협상) → LIST(상대 경로 목록 1000개씩, 수신 측이 경로 검증과 이어받기 힌트·디스크 여유 점검) → 파일마다 FILE_BEGIN(송신 측이 원본을 읽어 계산한 SHA-256 포함) → FILE_DATA 스트림 → FILE_END → FILE_RESULT, 마지막 SUMMARY/DONE. 수신 측은 `.pcmigrate-part` 에 쓰며 해시를 계산해 헤더와 같을 때만 확정하고(다르면 임시 파일 폐기 후 다시 받음, 기존 다른 파일은 `.bak` 보존), 이어받기는 `.part` 의 오프셋부터 이어 쓰되 해시는 처음부터 검증합니다.

**받는 쪽 안전**: 모든 경로를 검증해(`..`, 절대 경로, 드라이브 문자, `:` 데이터 스트림, 예약 이름, 끝의 점/공백, 길이, 링크를 거치는 위치) 받는 폴더 밖에는 절대 쓰지 않고, 받은 파일을 실행하지 않습니다. 디스크 여유를 먼저 점검하고, FAT32 드라이브에 4GB 넘는 파일이 오면 거부합니다(`--split-large` 는 이 방식에서 지원하지 않으니 NTFS/exFAT 폴더를 지정). 여러 원본/선택 파일은 `transfer --from-selection` 과 같은 `<받는 폴더>\<드라이브 문자>\<경로>` 구조로 받습니다(폴더 하나만 직접 주면 내용 그대로).

**진단(`send --diagnose`)**: 포트가 열려 있는지(거부 = 받는 프로그램 없음, 응답 없음 = 방화벽/공용 프로필 가능성), 서브넷이 같은지, 코드가 맞는지(오류/만료/잠김), 버전이 같은지를 한 줄로 알려 줍니다.

**한계**: 암호화 없음, 송신 PC 한 대씩, 같은 서브넷(또는 직결)만, 이어받을 때 완성된 파일도 해시로 다시 확인하므로 큰 폴더는 재개 시 읽기 시간이 듭니다(`--trust-existing` 같은 생략 옵션은 아직 없음), 파일마다 확인하므로 작은 파일이 수십만 개면 느립니다, 260자 넘는 경로의 기존 `.bak` 번호 충돌 확인은 일반 경로만 정확합니다. 프로그램에서 쓰려면 `pcmigrate.lan_api` 의 `start_receiver` / `discover_receivers` / `run_send` / `run_diagnose`(화면 없이 이벤트와 `ProgressInfo` 로 진행 전달).

## 다른 PC(구 PC)에서 실행하기

구 PC에는 이 도구가 없을 수 있습니다. 설치 없이 읽기 전용으로만 돌려도 되고, 아무것도 수정하지 않습니다.

1. **Python 3.10 이상 확인** — `python --version` (없으면 python.org 에서 설치, 다른 패키지는 필요 없음)
2. **저장소 받기** — GitHub 에서 zip 을 받아 풀거나 `git clone <저장소 주소>`
3. **설치 없이 실행(권장)** — 저장소 폴더에서:

   cmd:
   ```
   cd C:\path\to\pc-migration-tool
   set PYTHONPATH=src
   python -m pcmigrate scan
   ```
   PowerShell:
   ```
   cd C:\path\to\pc-migration-tool
   $env:PYTHONPATH = "src"
   python -m pcmigrate scan
   ```
   설치해서 쓰려면 `python -m pip install -e .` (이후 어디서나 `python -m pcmigrate`).

4. **구 PC에서 읽기 전용으로 돌릴 3개 명령** (출력 폴더는 저장소 밖으로, 예: USB `E:\`):

   cmd:
   ```
   python -m pcmigrate scan
   python -m pcmigrate discover --format md --output E:\pcm\discover.md
   python -m pcmigrate checklist --format md --output E:\pcm\checklist.md
   ```
   PowerShell:
   ```
   python -m pcmigrate scan
   python -m pcmigrate discover --format md --output E:\pcm\discover.md
   python -m pcmigrate checklist --format md --output E:\pcm\checklist.md
   ```
   `discover` 는 폴더 크기를 계산하느라 1분 안팎 걸릴 수 있고, 진행 상황이 화면(stderr)에 표시됩니다.

5. **결과 파일에는 개인 정보가 들어 있습니다**(설치된 프로그램 목록, 사용자 폴더 경로, 비밀 정보 가능성이 있는 폴더 이름).
   **저장소에 두거나 커밋하지 말고**, 남에게 공유하기 전에 내용을 확인하세요.

6. **인터넷이 없는 PC** — 이 도구는 외부 의존성이 없습니다. 저장소 폴더를 통째로 USB 나 공유 폴더로 복사한 뒤
   구 PC에서 위 3번처럼 `PYTHONPATH=src` 로 실행하면 됩니다(Python 3.10+ 만 설치되어 있으면 됩니다).
   `winget` 이 없거나 느려도 동작하며, 이 경우 winget 매칭은 건너뛰고 레지스트리 목록만 씁니다.

환경변수가 대소문자만 다른 중복(예: Git Bash 에서 `PROGRAMDATA=...` 로 지정)으로 의도와 다른 경로가 잡히면
`python -m pcmigrate --env PROGRAMDATA=D:\pd discover` 처럼 `--env NAME=VALUE` 로 경로 해석용 값을 덮어쓸 수 있습니다.

## 권장 사용 순서

구 PC에서(먼저 **Chrome 등 실행 중인 프로그램은 모두 닫고** 시작하세요. 실행 중이면 잠긴 파일은 읽지 못해 패키지에서 제외됩니다):
1. `python -m pcmigrate scan` — 설치된 프로그램을 감지하고 적용될 규칙을 확인
2. `python -m pcmigrate checklist --format md --output <폴더>\checklist.md` — 수동 작업 체크리스트 작성
3. `python -m pcmigrate export --output <폴더>\settings.zip` — 설정 패키지 내보내기(끊기면 같은 명령을 다시 실행하면 이어서 합니다. 처음부터 하려면 `--no-resume`)

신 PC에서:
4. `python -m pcmigrate import <settings.zip> --dry-run` — 무엇이 만들어지고 덮어써지는지 미리보기(쓰기 없음)
5. `python -m pcmigrate import <settings.zip> --yes` — 실제 복원(덮어쓸 파일은 `.bak` 백업)

`export` 와 `import --yes` 는 파일이 많으면 몇 분 걸릴 수 있어, 진행 상황을 10초마다(단계가 바뀔 때도) `[진행] 복원 파일 1,200/3,000개 …` 처럼 표준 오류로 보여 줍니다. `import` 는 먼저 패키지 전체를 검사하는 단계가 있어 이 동안은 줄이 나오지 않을 수 있습니다(파일 20,000개 규모에서 미리보기만 약 80초, 실제 복원은 5분 이상 걸린 측정이 있습니다).

사진/도면/프로젝트 같은 대용량은 설정 패키지가 아니라 `transfer`로 옮깁니다.
`python -m pcmigrate transfer <원본폴더> <대상> --dry-run` 으로 먼저 확인한 뒤 `--dry-run` 없이 실행하세요.
중단되면 같은 명령을 다시 실행하면 이어받습니다(`--strict` 는 모든 파일을 다시 해시 검증).

`transfer` 는 **대상 폴더에 기록 파일을 남깁니다**(원본에는 아무것도 쓰지 않습니다. 이 파일들은 다른 곳으로 복사되지 않습니다):

| 파일 | 용도 | 위치 바꾸기 |
|---|---|---|
| `.pcmigrate-state.json` | 이어받기 진행 상태(줄 단위 JSON: 검증 끝난 파일의 크기/수정 시각/해시) | `--state-file <경로>` |
| `.pcmigrate-robocopy.log` | robocopy 로그 | `--log <경로>` |
| `.pcmigrate-manifest.jsonl` | `--manifest-out` 을 줄 때만: 원본 기준 상대경로/크기/수정 시각/SHA-256 목록 | `--manifest-out <경로>` |

**상태 파일을 믿는 범위(한계)**: 기본 재실행은 상태 파일에 "검사 완료"로 적힌 파일을 **크기와 수정 시각이 같으면** 다시 읽지 않고 건너뜁니다(결과에 "이전 검사 기록을 믿고 다시 읽지 않은 파일 N개"로 알려 주고 리포트에 `trusted_state_files` 로 남깁니다). 그래서 크기·수정 시각이 같은 채 내용만 바뀐 경우(디스크 오류, 크기·시각을 맞춘 편집 등)는 `--strict` 로 실행해야 잡힙니다. 원본에서 크기·수정 시각이 바뀌지 않은 내용 변경도 같은 이유로 못 잡으므로, 중요한 이전은 마지막에 한 번 `--strict`(또는 `verify`)를 권장합니다.

상태 파일이 손상되었거나 원본 경로가 다르면 무시하고 전부 다시 검증합니다. 전송을 마친 뒤 지워도 됩니다(다음 실행 때 전체를 다시 검증).
`--strict` 는 상태 파일을 믿지 않고 모든 파일을 SHA-256 으로 다시 확인하며, 크기·수정 시각은 같은데 내용이 어긋난 파일은
원본에서 그 파일만 다시 복사합니다(어긋났던 사본은 `.bak` 으로 보존).

체크리스트는 `1. 새 PC 에서 먼저 설치 → 2. 로그인·인증 → 3. 데이터 복사/기타` 순서이고,
이 PC에 없는 프로그램 관련 경고는 생략됩니다(`--all` 로 모두 표시).

## 규칙 없는 프로그램 (discover)

`rules/*.json`은 알려진 프로그램을 정밀하게 처리하는 용도입니다. 규칙이 없는 설치 프로그램은 조용히 빠지지 않도록
`discover`가 별도로 찾아서 보여 줍니다(읽기 전용).

```
python -m pcmigrate discover                          # 규칙 없는 프로그램과 설정 폴더 후보
python -m pcmigrate discover --format md --output <폴더>\discover.md
python -m pcmigrate discover --all                    # 제조사 번들, 규칙 쪽 폴더, 연결 못 한 폴더까지
python -m pcmigrate discover --min-size-kb 10         # 작은 폴더 숨김
python -m pcmigrate discover --output-selection <폴더>\selection.json
```

- 후보 위치: `%APPDATA%`, `%LOCALAPPDATA%`(캐시/임시 제외), `Documents`(OneDrive 후보 포함), `%PROGRAMDATA%`,
  `%USERPROFILE%` 바로 아래 점 폴더/파일(`.gitconfig`, `.ssh`, `.m2` 등).
- 프로그램과의 연결은 폴더 이름, 발행자, 설치 위치로 추정하고 근거 등급(확실/추정)을 표시합니다. 크기는 시간 상한이 있어
  오래 걸리면 "크기 미확인"으로 나옵니다.
- `.ssh`, `.aws`, 쿠키, 토큰, credentials 등이 들어 있을 수 있는 항목에는 "비밀 정보 가능성" 경고가 붙고 기본 제외입니다.

**처리 원칙: 자동 포함 안 함, 선택 후 포함.** discover 는 아무것도 export 에 넣지 않습니다. 포함하려면
`--output-selection`으로 만든 선택 파일(모두 `include: false`)에서 필요한 항목만 `true`로 바꾸고
`export --extra <선택파일>`로 지정합니다. 비밀 정보 가능성이 있는 항목은 `--allow-secrets`를 한 번 더 붙여야 하고,
신 PC에서 복원할 때도 `import --yes --allow-extra`가 필요합니다(`--dry-run`으로 먼저 확인).
**프로그램 하나만 자세히:** `discover --program "이름"`(GUI 2단계의 "이 프로그램 설정 찾기")은 그 프로그램의 이름/게시자/설치 경로에서 뽑은 단어로 AppData, Documents, ProgramData, 홈의 점 폴더를 이름으로 찾고(시간 상한 `--find-time-limit`, GUI에서는 취소 가능), 각 후보에 크기, 파일 수, 근거(일치한 단어), 신뢰 등급을 붙입니다. 전체 탐색과 달리 캐시/로그/임시 폴더도 찾아 `임시 저장물일 수 있음`/`로그` 배지로 구분하고(자동 선택 없음, 직접 고르면 그대로 담김), 라이선스 폴더는 발견만 표시하며 선택할 수 없습니다(이 도구는 라이선스를 옮기지 않습니다). 설치 폴더(Program Files 등)의 설정 형식 파일(`.ini .json .xml .cfg .config .conf .properties .yaml .yml .toml .pgp .cui .cuix`)은 '설치 폴더 설정' 배지가 붙은 체크 가능한 후보로 보여 주며 자동으로 선택하지 않습니다. 선택 파일에는 `install_dir` 목록으로 따로 담기고(이전 버전은 이 목록을 무시합니다), 내보내면 패키지의 `data/install/` 영역에 환경 토큰 경로(`%ProgramFiles%` 등, 사용자 이름 경로 없음)로 담기며 설정 확인표에 '설치 폴더 설정' 행으로 나옵니다. 실행/스크립트/라이브러리/라이선스/링크, 파일당 5MB·프로그램당 30개/20MB·전체 300개/50MB를 넘는 것은 제외하고 사유를 기록합니다.

**설정 파일 없음 판정:** `discover --program` 과 후보 목록(JSON 의 `no_config_found`, `config_check`: `있음 N개`/`없음`/`확인 안 됨`)은 허용 방식 기준 설정 형식 파일이 0개이고 계산이 시간 상한 없이 끝난 후보를 "설정 파일로 보이는 파일이 없습니다(폴더 용량 X는 설정 형식이 아닌 파일입니다. 필요하면 --extra-mode all)"로 알립니다(설치 폴더 탐색 결과 포함, 시간 상한에 걸리면 `확인 안 됨`). GUI 2단계 표는 이를 회색 "없음"으로 보여 주고, 체크하면 담을 파일이 없다는 안내를 띄웁니다(폴더 전체 담기를 켜면 해당 없음).

**자체 이전 필요 표시:** 카카오톡 대화, 금융보안·키보드 보안 모듈(TouchEn nxKey, nProtect, AhnLab Safe Transaction, Veraport 등), 공동(공인)인증서 도구, 백신, 그래픽/오디오 드라이버, Microsoft Office, Adobe Creative Cloud 처럼 폴더를 복사해서는 옮길 수 없는 프로그램은 `selftransfer/self_transfer.json` 에 이름 패턴(설치 프로그램 표시 이름/게시자/폴더 이름), 분류, 이유, 대신 할 일, 근거 등급(A/B)으로 적혀 있습니다. `selftransfer/` 에 `*.json` 을 더하면 코드 수정 없이 항목이 늘어납니다(스키마 검증, `check-rules` 가 항목 수 보고, exe 와 pip 설치에도 함께 들어갑니다). `discover`/`discover --program` 은 해당 후보에 `자체 이전 필요: 이유 / 대신 할 일` 한 줄을 붙이고 JSON 에는 `self_transfer`(id/name/category/reason/todo)를 넣으며, 선택 파일에는 `self_transfer` id 만 덧붙입니다. 내보낼 때 이런 항목을 골라도 막지 않고 경고(와 설정 확인표/패키지 기록의 덧붙인 표시)만 남깁니다. GUI 2단계 표는 이 후보를 메인 표에서 빼고 표 아래의 접힌 구역 "자체 이전이 필요한 프로그램 N개 ▸"에 모읍니다(배지, 프로그램, 대신 할 일; 줄을 고르면 상세 줄, 체크하면 안내 창, "전체 선택"은 이 구역을 선택하지 않음). 이름만으로 판정하는 목록이라 이름이 다르게 설치된 프로그램은 빠질 수 있고, 여러 프로그램이 함께 쓰는 제조사 폴더는 근거가 약하면 표시하지 않습니다.

**설치 폴더 설정 복원(기본은 복원 안 함):** `import --allow-install-dir`(GUI 신 PC 미리보기의 '설치 폴더 설정도 복원')을 켠 경우에만 복원하며, (1) 프로그램 폴더가 새 PC에 이미 있어야 하고(없으면 건너뛰고 '먼저 프로그램을 설치한 뒤 다시 복원하세요'), (2) `%ProgramFiles%`/`%ProgramFiles(x86)%` 또는 새 PC에서 같은 이름 프로그램의 설치 위치 아래이며 링크/정션, `..`, 대체 데이터 스트림, 예약 이름, Windows 구성요소 폴더, 다른 프로그램 폴더는 거부하고, (3) 설정 형식 확장자만 쓰며(변조된 묶음의 exe/dll/스크립트는 거부), (4) 기존 파일은 `.bak`으로 보존하고 미리보기에 덮어쓸 목록을 보여 주며, (5) 쓰기 권한이 없으면 '관리자 권한으로 다시 실행해 주세요'를 안내하고 아무것도 쓰지 않고 멈추며, (6) '같은 버전의 프로그램에서 가져온 설정 파일이라 버전이 다르면 오작동할 수 있다'는 경고를 보여 줍니다. 라이선스는 이 경로로도 옮기지 않습니다. 프로그램별 복원 선택에서는 설치 폴더 설정이 `install`(전부) 또는 `install:<프로그램 이름>` 단위로 선택/제외되고(`--only`/`--skip`), 복원 기록에 `install: true` 로 남아 `undo-import`가 `.bak`을 되돌립니다(권한이 없으면 "관리자 권한으로 다시 실행해 주세요"). 설치 폴더 확장자 허용 목록은 허용 방식(`--extra-mode config`)의 허용 목록의 부분집합입니다.

**캐시 자동 제외:** 직접 고른 폴더 안의 다시 만들어지는 폴더(이름이 정확히 `Cache`, `Code Cache`, `GPUCache`, `GrShaderCache`, `ShaderCache`, `DawnCache`, `Crashpad`, `Crash Reports`, `logs`, `node_modules`, `Service Worker/CacheStorage`)는 기본으로 빼고 이름/파일 수/용량을 기록합니다. `export --include-caches`(GUI 고급 옵션 "캐시 폴더도 포함")로 포함합니다. 규칙 경로 안은 규칙의 exclude 가 정합니다.

**설정 확인표:** 내보내기 직후(CLI 요약, GUI 결과)와 `import` 미리보기에 프로그램 / 옮기는 설정 / 상태(담김, 일부만 담김, 이 PC에 없음, 읽지 못함, 직접 해야 함, 제외됨) / 담긴 파일 수가 나옵니다. 이 PC에 없는 설정 위치는 "해당 없음 N곳" 한 줄로 접힙니다(manifest 의 `coverage` 항목, 이전 패키지도 읽힙니다).

포함된 항목에도 export의 기존 안전장치(원본 읽기 전용, 해시 manifest, `*.lic` 제외, 허용 루트 검증, zip 슬립 방어)가 적용됩니다.

`scan`, `checklist`, `export` 마지막에 "규칙 없는 설치 프로그램 N개, 설정 폴더 후보 M개"가 출력됩니다.

## 경로에 환경변수를 쓸 때 (cmd vs PowerShell)

| 셸 | 임시 폴더 예 |
|---|---|
| cmd | `%TEMP%\checklist.md` |
| PowerShell | `$env:TEMP\checklist.md` |
| Git Bash | `$TEMP/checklist.md` |

셸에 맞지 않는 표기는 확장되지 않은 채 들어옵니다. 이 도구는 `%TEMP%`, `$env:TEMP` 가 남아 있으면
폴더를 만들지 않고 오류와 힌트를 출력한 뒤 종료 코드 1로 끝납니다.

## 내보내기가 중간에 끊겨도 이어서 합니다 / 압축 생략

`export` 는 만드는 동안 최종 이름(`settings.zip`)이 아니라 같은 폴더의 **`settings.zip.part`**(만드는 중인 zip)와
**`settings.zip.part.journal`**(진행 기록)에 씁니다. 다 만들고 전체 검사를 통과한 뒤에만 최종 이름으로 바꾸므로(같은 이름의 완성본이 있으면
`.bak` 으로 보존), **최종 이름의 파일은 항상 완성본**입니다. `.part` 파일은 가져오기(`import`)가 거부합니다.

- **이어받기(기본 켬)**: 오류, 취소, 전원 차단, 강제 종료로 끊긴 뒤 **같은 저장 위치로 다시 내보내면 이어서 합니다.**
  파일 256MB 또는 60초 중 먼저 오는 쪽마다 저장점을 찍고(zip 을 디스크에 확정한 뒤 진행 기록에 "여기까지 확정"을 남김), 다시 시작하면
  마지막 저장점까지는 다시 담지 않고 그 뒤부터 합니다. 시작할 때 `[이어받기] 이어서 하는 중: 저장점까지 N개 파일(…)을 보존했습니다.` 가 나오고,
  GUI 현황 카드에도 "저장점에서 이어받음 N개 파일"이 보입니다. GUI 는 내보내기 전에 이어받을 수 있으면 안내 한 줄과
  "처음부터 다시 만들기" 체크 상자를 보여 줍니다(체크하면 확인 문구 뒤에 임시 파일을 지우고 처음부터 합니다).
- **처음부터 다시 만들기**: `--no-resume`(또는 `--restart`). 이전 `.part`/`.part.journal` 을 무시하고 지운 뒤 새로 만듭니다.
  지우는 것은 이 도구가 만든 이 두 임시 파일뿐이며 완성본과 원본은 건드리지 않습니다.
- **안전장치(19a)**: 같은 출력 이름으로 동시에 내보내면 `<출력>.part.lock`(PID)이 막고, `.part`/`.part.journal` 은 **머리를 확인해 이 도구가 만든 것일 때만** 지웁니다(이름만 같은 다른 파일이면 지우지 않고 "다른 출력 이름을 쓰세요"). 출력 파일이 백업할 폴더 안이면 시작하지 않고, 저장 드라이브의 여유 공간/FAT32 4GB 한계를 만들기 전에 점검하며(`transfer` 와 같은 검사), 강제 종료로 남은 `.pcmigrate-stage-*` 임시 폴더는 다음 실행 때 주인이 없으면 치웁니다. 260자가 넘는 경로의 파일도 담고, 읽지 못한 폴더는 조용히 넘기지 않고 `failed` 에 기록합니다. 만든 패키지의 최종 검사가 실패하면 임시 파일을 바로 지우지 않고 `<출력>.part.failed` 로 보존하고 안내합니다(다시 내보내면 처음부터 만들고, 성공하면 보존본을 지웁니다).
- **자동으로 처음부터 하는 경우**(이유를 한국어로 알려 줍니다): 선택한 프로그램/규칙 버전/직접 고른 항목/압축 설정/도구 버전이 이전과 다름,
  진행 기록이 깨졌거나 `.part` 가 기록과 맞지 않음, 기록 없이 `.part` 만 있음. 원본 파일의 크기나 수정 시각이 바뀌었거나 사라진 파일은 그 파일만 다시 담습니다.
  읽지 못해 제외된 파일(Chrome 실행 중 등)은 기록에는 남지만 **다음 시도에서 다시 읽어 봅니다**(프로그램을 닫은 뒤 이어서 하면 들어갑니다).
  이어받은 결과도 처음부터 만든 것과 똑같이 전체 검사(크기/SHA-256)를 통과해야 하며, 통과하지 못하면 임시 파일을 버리고 자동으로 처음부터 다시 만듭니다.
- **한계**: 저장점은 파일 단위입니다. 파일 하나가 매우 크면(수 GB) 그 파일을 담는 도중에 끊긴 경우 그 파일은 처음부터 다시 담습니다.
  실패/취소 후에는 `.part` 와 `.part.journal` 이 남습니다(디스크 공간을 차지하므로 포기할 때는 직접 지워도 됩니다).
- **`--compress auto|always|never`**(기본 `auto`): `auto` 는 이미 압축된 형식(`.jpg .jpeg .png .gif .webp .heic .mp4 .mov .mkv .zip .7z .rar .gz .pdf .docx .xlsx .pptx` 등)과,
  8MB 이상이면서 앞/가운데/끝 표본이 10% 이상 줄지 않는 파일을 **압축 없이(STORED)** 담아 시간을 줄입니다. `.rvt .dwg .3dm .skp` 같은 CAD/BIM 형식은
  압축률을 확신할 수 없어 목록에 넣지 않았고(큰 파일은 표본으로 판단), 나머지는 deflate 로 압축합니다. `always` 는 모두 압축, `never` 는 모두 생략입니다.
  패키지의 `manifest.json` 에 `compress` 와 파일별 `method`(stored/deflated)를 기록하며, 가져오기는 두 방식을 모두 처리합니다.
  가짜 데이터(합계 136MB: 텍스트형 CAD 40MB, jpg 형 60MB, 압축 안 되는 24MB 1개, 압축되는 12MB 1개) 측정에서 `always` 10.4초/101MB,
  `auto` 5.1초/101MB(같은 용량), `never` 1.1초/136MB 였습니다(이 PC 기준 한 번 측정, 장치와 데이터에 따라 다릅니다).

## 읽지 못한 파일, 입력 검사, 원본 보호 (v0.1.1)

- **실행 중인 프로그램이 잠근 파일**(예: Chrome 이 실행 중일 때 `User Data` 의 `LOCK` 파일)은 읽을 수 없습니다. `export` 는 그런 파일을
  패키지에 **흔적 없이 제외**하고(임시 저장소에 먼저 끝까지 읽은 뒤 성공했을 때만 zip 에 기록) `manifest['failed']` 에 "사용 중이라 읽지 못함"으로
  남긴 채 끝까지 진행하며, 결과에 "읽지 못해 제외된 파일 N개(예: Chrome 실행 중이면 닫고 다시 하세요)"와 예시 경로 5개를 보여 줍니다.
  패키지를 만든 직후 다시 검사해 문제가 있으면 임시 파일을 남기지 않고 어떤 항목이 문제인지 알려 줍니다.
  `LOCK`, `lockfile`, `parent.lock`, `SingletonLock`, `SingletonCookie`, `SingletonSocket` 은 복사할 가치가 없어 항상 제외합니다.
- **목록 밖 프로그램은 '설정 파일만' 담기(`export --extra-mode config|all`, 기본 `config`)**: 규칙이 없는 프로그램의 폴더(`--extra`)에서 예전에는
  캐시만 빼고 폴더 전체를 담아 용량이 크고 정크가 섞였습니다. 기본은 허용 방식으로, `src/pcmigrate/settings_filter.py` 의 확장자 표(`ALLOWED_CONFIG_EXTS`, 근거 등급 A/B/C)에 있는
  파일만 담습니다. A(텍스트 설정 표준): `.ini .cfg .conf .config .json .jsonc .xml .yaml .yml .toml .properties .code-snippets`;
  B(건축 CAD/BIM 사용자 정의, 공식 문서에 설정/템플릿으로 적힌 형식): `.pgp .cui .cuix .mns .dwt .ctb .stb .pc3 .pmp .lin .pat .rte .rft .rui .plist`;
  C(프로그램/버전별 편차, 현장 확인 권장): `.bpx .bfx .tpl`; 확장자 없는 점 파일은 `.gitconfig .gitattributes .editorconfig .gitignore_global` 만 허용합니다.
  **허용하지 않는 것**: 실행/스크립트/라이브러리(복원도 거부), 라이선스(`.lic`, 이름에 license/eula), 로그, 캐시/임시/잠금, DB·바이너리(`.db .dat .bin`),
  이미지/영상, 작업물(`.dwg .rvt .skp .3dm`), `.txt/.csv`(설정인지 메모인지 구별 불가), 글꼴, `desktop.ini`. `.reg` 는 더블클릭만으로 레지스트리를 바꾸는 실행성 파일이라
  의도적으로 제외합니다(복원 거부 목록에도 있음). **상한**(폴더 항목 하나 기준, 정렬 순서대로 적용): 파일 하나 32MB, 폴더 256MB, 파일 5000개를 넘는 것은 담지 않고 사유(`limit`)를 기록합니다.
  설정 형식이 아니라 뺀 파일은 파일마다가 아니라 폴더마다 요약(`manifest['skipped']` 의 `not_config`: 개수, 용량, 확장자별 개수)으로 기록하고, 설정 확인표(`coverage`)에
  `config_mode/allowed_files/ext_counts/not_config_files/not_config_bytes/limit_files` 를 덧붙입니다(기존 키는 그대로, 이전 패키지도 읽힘). `--extra-mode all` 은 예전 방식입니다.
  선택은 이어받기 지문에 들어가 바꾸면 처음부터 다시 만들고, `--retry-failed` 는 묶음에 기록된 모드와 상한으로 다시 찾습니다(기록 없는 이전 묶음은 `all`).
  `discover --program` 의 후보에는 허용 방식 기준 '담길 파일 수/용량, 설정 형식이 아니라 빠질 파일'이 함께 나옵니다(JSON 의 `config_files` 등).
  확장자 없는 설정 파일(예: `Preferences`)은 허용 방식에서 빠지므로 필요하면 `--extra-mode all` 을 쓰세요.
  **빠진 파일 예시:** 폴더(항목)마다 빠진 파일 중 큰 것 최대 5개의 이름(항목 폴더 기준 상대 이름)·크기·사유만 기록합니다(훑는 중 얻은 이름/크기/확장자만 쓰며 추가 순회·파일 읽기는 없고, 파일당 O(log 5) 힙). `manifest['skipped']` 의 `not_config` 항목에 `examples: [{name, size, why}]` 와 사유별 개수 `by_reason`(데이터베이스/데이터, 확장자 없음(설정일 수 있음), 작업물·모델, 글꼴, 이미지·영상, 메모 문서, 로그, 라이선스, 실행·라이브러리·스크립트, 크기 상한, 기타; 분류표는 `settings_filter.why_of`)을, 설정 확인표 항목(`coverage`)에 `excluded_by_reason`/`excluded_examples` 를 덧붙입니다(없는 이전 패키지도 읽힘). 확인표에는 `제외 N개, 3.0GB(사유 요약)` 한 줄과 예시가 나오고, `export --json` 의 `coverage` 행에도 `excluded_files/excluded_bytes/excluded_by_reason/excluded_examples` 가 들어갑니다. GUI 설정 확인표(구 PC 마지막 화면, 신 PC 미리보기)는 행 아래에 같은 한 줄을 보이고 `자세히 ▸`(줄을 누르거나 Enter)로 예시를 펼치며, 확장자 없는 파일이 빠졌으면 노란 안내가 한 줄 나옵니다.
- **프로그램별 복원 선택(`import --only 규칙id[,..]` / `--skip 규칙id[,..]`)**: 새 PC 에서 일부 프로그램만 복원하거나 뺍니다. 프로그램 단위는 규칙 id,
  규칙 없는 항목은 `extra:<루트키>/<최상위 이름>`(예: `extra:appdata/AcmePaint`; `extra` 는 전부, `extra:AcmePaint` 는 루트 무관). `--only` 후 `--skip` 을 적용하고, 묶음에 없는 이름은 오류로 알립니다.
  `--dry-run`/`--json` 미리보기에는 프로그램별 표(`programs`: id, name, kind, selected, files, bytes, new, overwrite, same, denied, rejected, not_selected)가 나옵니다.
  뺀 프로그램은 대상 파일을 읽지도 쓰지도 않고 상태 `not_selected`('선택에서 제외됨')로 기록하며 `--allow-extra` 도 요구하지 않습니다. 허용 범위/해시 검증/링크 거부는 선택과 무관하게 똑같이 적용합니다.
- **프로그램별 되돌리기(`pcmigrate undo-import --only 규칙id[,..]`)**: `import --yes` 가 끝나면 복원 기록(`%LOCALAPPDATA%\pcmigrate\import-records\import-YYYYMMDD-HHMMSS.json`,
  `--record-dir` 로 바꿈, 리포트 `meta.import_record` 에도 경로)을 남깁니다. 형식: `{format:"pcmigrate-import-record", version:1, created, package, programs[], entries[]}`,
  entries 항목은 `program, entry, target, base_dir, backup, backup_size, backup_sha256, new_size, new_sha256, undone, undone_at, undo_action`(실제로 복사한 파일만).
  `--dry-run` 으로 미리 보고 `--yes` 로 실행합니다(기본은 가장 최근 기록, `--record` 로 지정). 덮어썼던 파일은 `.bak` 이 기록한 크기/해시 그대로이고 대상이 복원한 그대로일 때만 `.bak` 을 원래 이름으로 되돌립니다.
  `.bak` 이 없거나 바뀌었거나 복원 뒤 사용자가 고친 파일은 되돌리지 않고 이유를 알립니다. 복원이 새로 만든 파일은 **지우지 않고** '새 파일 N개는 지우지 않았습니다'로 알리며 `--move-new` 면 `<이름>.removed` 로 옮깁니다.
  기록 파일은 신뢰하지 않고 허용 루트/링크/`.bak` 이름을 다시 확인하며, 두 번 실행해도 안전합니다(되돌린 항목은 기록에 표시).
- **읽지 못해 제외된 파일만 다시 담기(`export --retry-failed`)**: 해당 프로그램(예: Chrome)을 닫은 뒤 `pcmigrate export --output 묶음.zip --retry-failed`
  (GUI: 결과 영역의 "이 파일들만 다시 담기")를 실행하면 새로 만들지 않고, **이미 만든 묶음**의 `manifest['failed']` 항목만 현재 원본에서 다시 읽어 그 묶음에 추가합니다.
  담을 대상은 묶음에 적힌 규칙 id 와 직접 고른 항목(`extras`)으로 다시 찾으므로(이 PC 의 `--rules` 폴더에 같은 규칙이 있어야 함) 규칙 밖이거나 보안상 거부 대상인 파일은 다시 담지 않습니다.
  기존 묶음 내용은 재압축 없이 `<묶음>.retry` 로 그대로 옮기고 추가분을 담아 전체 검사를 통과해야만 교체하며, 이전 묶음은 `.bak` 으로 보존합니다(실패/취소/계속 잠긴 경우 원래 묶음은 바뀌지 않음).
  처음 내보낸 뒤 원본이 바뀌었어도 **지금 원본의 내용**을 담습니다. 담긴 파일은 `manifest['files']` 에 추가되고 `failed` 에서 빠지며(`retries` 기록이 남음), 계속 못 담은 파일은 `failed` 에 남고 원인(사용 중/권한/경로 길이 등)과 함께 표시됩니다.
  `--extra/--allow-secrets/--restart/--compress` 와는 함께 쓸 수 없고, 묶음이 없거나 `.part`(끝나지 않은 임시 파일)이거나 검사에 실패하면 쉬운 오류로 멈춥니다. `--json` 지원. 같은 이름의 내보내기와 동시에 실행되지 않도록 `.part.lock` 을 씁니다.
- `--chunk-mb`(0.25~1024), `--workers`(1~8), `--copy-threads`(1~16)는 범위를 벗어나면 조용히 바꾸지 않고 종료 코드 2 와 한국어 오류를 냅니다.
- 깨졌거나 UTF-8 이 아닌 해시 목록(`.jsonl`)과 패키지 `manifest.json` 은 traceback 없이 "해시 목록 오류" / "패키지 검증 실패" 로 안내합니다.
- 원본 폴더 안에는 아무것도 쓰지 않습니다: `transfer` 의 `--report/--log/--state-file/--manifest-out`, `manifest --out`, `copy --report` 가 원본 폴더 안
  (정션·대소문자 차이 포함)이면 시작하지 않습니다. GUI 의 결과 파일 저장도 같습니다.
- `export/discover/checklist --output` 에 기존 **폴더**를 주면 거부합니다(폴더를 `.bak` 으로 바꾸고 같은 이름의 파일을 만드는 일이 없도록).
  `import --report` 가 패키지 파일 자신이면 거부합니다. 빈 문자열 경로("")는 현재 폴더로 보지 않고 오류로 처리합니다.
- **임시 폴더 위치(`export --stage-dir <폴더>`)**: 64MB 넘는 파일을 담기 전에 임시로 읽어 두는 `.pcmigrate-stage-*` 폴더는 기본으로 출력 파일 옆에 만듭니다. 출력이 느린 외장/네트워크 드라이브면 로컬 디스크 폴더를 지정하세요. 원본(백업할) 폴더 안은 거부하고(원본 안에는 폴더도 만들지 않음), 임시 폴더는 성공/실패와 상관없이 끝나면 지우며, 임시 폴더가 다른 드라이브면 가장 큰 파일 하나 분량의 여유 공간을 그 드라이브에서 따로 점검합니다.
- **`.gitconfig` 복원 경고**: `.gitconfig` 복원은 허용하지만 명령 실행 설정(`core.sshCommand`, alias 의 `!명령` 등)이 들어 있을 수 있어, 복원 미리보기/결과 요약에 "복원 전에 내용을 확인하세요" 경고 한 줄을 냅니다(리포트에는 `git_config_warning` 키).
- 규칙 폴더(`rules/`, `--rules` 로 바꾼 폴더 포함)가 없거나 규칙 파일(`*.json`)이 하나도 없으면 `scan/discover/checklist/export/import` 모두 "규칙 오류: 규칙 폴더를 찾을 수 없습니다 …" 한국어 안내와 종료 코드 1 로 멈춥니다(빈 패키지를 만들지 않습니다). 프로그램 폴더의 `rules` 가 지워졌다면 다시 내려받으세요.
- GUI 가드: 작업 중에는 다른 작업을 시작할 수 없고(창을 닫으면 확인), 패키지 저장 위치가 폴더이거나 `%TEMP%` 같은 환경변수 표시가 그대로면 거부합니다. 대용량 복사에서 "클라우드 파일 포함"/"엄격 검사" 옵션을 미리보기 뒤에 바꾸면 미리보기가 무효가 되어 다시 "미리보기 실행"을 해야 복사할 수 있습니다. 복원이 실패하거나 끝나면 확인 표시가 모두 지워져, 다시 복원하려면 미리보기부터 해야 합니다. 화면 갱신 중 오류가 나도 진행 표시와 버튼 상태는 복구되고 오류 대화상자로 알려 줍니다.

## 덮어쓰기와 .bak, 규칙별 복원 범위, 프로그램 설치

**덮어쓰기와 `.bak`**

| 작업 | 대상에 같은 이름 파일이 이미 있을 때 |
|---|---|
| `import --yes` / GUI 복원 | 덮어쓰기 전에 `<이름>.bak` 으로 백업합니다(이미 있으면 `.bak.1`). 같은 내용이면 건너뜁니다. |
| `copy` (소규모) | 덮어쓰기 전에 `.bak` 으로 백업합니다. |
| `transfer` (대용량) | 복사(robocopy) **시작 전에** 대상에 있는 같은 이름의 **다른** 파일(크기가 다르거나 수정시각이 2초 넘게 다름)을 같은 폴더의 `<이름>.bak`(이미 있으면 `.bak.1`)으로 **이름만 바꿔 보존**한 뒤 복사합니다(데이터를 다시 쓰지 않아 빠르지만, **기존 파일은 `.bak` 으로 남아 공간을 계속 차지하고 새 파일 크기만큼 여유 공간이 더 필요합니다** — 여유 공간 검사와 `--dry-run` 이 이를 반영하고, 같은 대상에 여러 번 실행하면 `.bak` 이 쌓이니 확인한 뒤 직접 지우세요). 같은 파일은 건드리지 않습니다. `--dry-run` 이 덮어쓸 파일 수를 경고로 알려 주고, 실제 실행 뒤 리포트의 `preserved_existing_count`/`preserved_existing`(앞 200개)에 기록합니다. 보존에 실패하면(파일 사용 중 등) **복사를 시작하지 않고** 멈추며, 그때까지 `.bak` 으로 옮긴 파일은 원래 이름으로 되돌립니다(되돌리지 못한 파일이 있으면 그 이름을 알려 줍니다. 아무것도 덮어쓰지 않음). `--strict` 로 다시 복사할 때 내용이 어긋난 사본도 `.bak` 으로 남깁니다. |
| `export/discover/checklist --output` | 같은 이름 파일이 있으면 `.bak` 으로 보존합니다. |

**규칙별 복원 범위** (`rules/*.json` 22개). 복원할 폴더/파일 경로가 있는 규칙과, 감지해서 수동 작업만 안내하는 "경고 전용" 규칙이 있습니다.

| 구분 | 규칙 |
|---|---|
| 설정/템플릿 폴더를 패키지에 담고 복원 (10) | AutoCAD, Civil 3D, Enscape, JetBrains, Lumion, QGIS, Revit, Rhino, SketchUp, VS Code |
| **경고 전용: 감지해서 수동 작업만 안내, 파일은 복원하지 않음 (12)** | ArchiCAD, ArcGIS Pro, Bluebeam, 웹 브라우저(Chrome/Edge/Firefox), EzLoad(이지로드), GeoStudio, MicroStation, MIDAS, Navisworks, PLAXIS, Trimble Business Center, V-Ray |

**보안상 복원하지 않는 형식**: 실행/스크립트/라이브러리 형식(`.exe .dll .js .py .bat .lnk .msi .jar .xll .chm` 등), 시작 프로그램/XLSTART 폴더, 셸·SSH 시작 설정, 홈의 `.npmrc/.wslconfig/.condarc/.kube/config/.docker/config.json` 등은 `export` 때 같은 판정으로 패키지에서 빼고(경고와 `manifest.skipped` 의 `denied`), `import` 때는 **패키지 전체를 막지 않고 그 파일만 "복원 안 함(denied)"** 으로 표시한 채 나머지를 정상 복원합니다(결과/리포트에 항목별로 남고 실패로 세지 않습니다. 변조된 패키지가 이 위치에 쓰려 해도 쓰지 않습니다). 규칙이 마지막 경로 패턴에 `*.dll` 처럼 그 확장자를 직접 적어 둔 경우에만 그 규칙에서 허용합니다. 예: QGIS 플러그인의 `.py` 는 복원되지 않으므로 신 PC 에서 플러그인 관리자로 다시 설치하세요.

경고 전용 프로그램의 설정은 각 프로그램의 자체 내보내기/동기화 기능으로 옮기세요(체크리스트에 안내가 나옵니다). 위 표의 근거 등급(원문/요약/미검증)은 각 규칙 파일의 `notes` 에 있습니다.

**프로그램 설치는 안내만 합니다.** `export` 는 설치 목록(`winget export` 와 레지스트리)을 패키지에 담고, 신 PC 의 `checklist --package` 와 GUI 체크 목록이
**`winget import -i winget.json ...` 와 `winget install --id ...` 명령을 문장으로 보여 줄 뿐**, 도구가 `winget import` 나 설치를 자동으로 실행하지는 않습니다. 보여 준 명령을 직접 실행하세요.
패키지 안의 winget 목록은 `python -m pcmigrate winget-extract <settings.zip> --output <폴더>` 로 `<폴더>/winget.json` 에 꺼냅니다(패키지를 먼저 검증하고, 같은 이름의 파일이 있으면 `.bak` 으로 보존하며, 이어서 실행할 `winget import` 명령을 보여 줍니다).
winget 에 없는 프로그램은 "수동 설치" 목록으로 안내합니다. 라이선스는 복원하지 않습니다.

### 프로그램 설치 확인 (새 PC, 읽기 전용)

설정 묶음 파일의 구 PC 설치 목록(`programs/registry.json`, `programs/winget.json`)과 **새 PC의 현재 상태**(레지스트리 + `winget export`/`winget list`)를 비교해
어떤 프로그램이 이미 설치됐고 어떤 것이 안 깔렸는지 자동으로 판정합니다. GUI 는 새 PC 흐름의 "프로그램 설치 확인" 화면(설정 묶음 파일 선택 다음, 건너뛰기 가능)이고,
명령줄은 `python -m pcmigrate install-check <settings.zip> [--json]` 입니다(사람이 읽는 한국어 요약 + 다음 할 일 한 줄, 할 일이 남아도 종료 코드 0, 오류만 1).

| 판정 | 뜻 |
|---|---|
| 설치됨 | 새 PC 에 winget id 가 같거나 이름이 같은 항목이 있음(확실). 버전이 다르면 `버전 다름(구 x → 새 y)` 을 함께 표시 |
| winget 으로 설치 가능 | 설치돼 있지 않고 묶음의 winget 목록(또는 대표 앱 표)에 있음. 새 PC 의 winget 에 실제로 있는지는 `winget import` 가 판단합니다 |
| 수동 설치 필요 | 설치돼 있지 않고 winget 으로 확실하게 연결되지 않음(체크리스트의 수동 설치 문구와 힌트 재사용) |
| 애매함 | 이름만 비슷한 추정 일치(같은 제품의 다른 연도, 이름 일부 일치 등). 근거 등급 '추정' 과 사유를 표시하며 직접 확인해야 합니다 |
| 설치 불필요 | 제조사 번들/드라이버/런타임/Windows 기본 포함 |

도구는 `winget import` 나 설치를 **자동으로 실행하지 않습니다**(권한 문제와 안전을 위해). GUI 의 `설치 목록 꺼내고 명령 복사` 버튼은 묶음의 `winget.json` 을
고른 폴더(기본: 바탕화면의 `PC이전-프로그램목록`)에 꺼내 `winget import ...` 명령을 클립보드에 복사할 뿐이며, 명령 창에서 직접 붙여넣어 실행한 뒤
`다시 확인` 을 누르면 새 PC 상태를 다시 읽어 판정하고 "지난 확인보다 새로 설치된 프로그램 N개" 를 보여 줍니다. 수동 설치 항목은 '표시' 칸으로 설치 끝냄을 기억해 둘 수 있습니다(표시는 판정에 쓰이지 않음).
한계: 이름과 winget id 로 추정하므로 설치 프로그램 표시 이름이 다른 앱은 '애매함' 이나 '수동 설치 필요' 로 잘못 나올 수 있고(과다 안내 쪽으로 기웁니다),
새 PC 에서 winget 을 읽지 못하면 이름 기준으로만 판정해 정확도가 낮다는 안내가 붙습니다.

## 개인정보 주의

`checklist`, `export`, `transfer --report` 의 출력 파일에는 이 PC에 설치된 프로그램 목록과 파일 경로가 들어갑니다.
저장소 안에 두거나 **커밋하지 마세요**(공유 전에 내용을 확인하세요). `.gitignore` 가 `checklist*.md`, `discover*.md`, `*.bak`, `*.jsonl`,
`.pcmigrate-*` 등을 막아 주지만 안심하지 말고 확인하세요. **오류 로그(`errors-*.log`)에도 파일 경로가 들어 있으니 공유 전에 확인하세요.** 라이선스는 복원되지 않습니다.
